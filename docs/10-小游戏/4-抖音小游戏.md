# 抖音小游戏

全局对象 `tt`，Cocos 构建目标 `bytedance-mini-game`。字节生态（抖音 / 今日头条 / 西瓜 / 抖音极速版）通投。

## 和微信的核心差异

| 维度 | 微信小游戏 | 抖音小游戏 |
|------|-----------|-----------|
| 全局对象 | `wx` | `tt` |
| 主包限制 | 4MB | **20MB**（宽松得多） |
| 分包总量 | 30MB | 30MB |
| 流量来源 | 社交裂变（分享、群） | **信息流买量 + 短视频引流** |
| 变现主力 | 内购 + 广告 | **激励广告**（eCPM 普遍更高） |
| 好友排行 | 开放数据域（架构特殊） | 无同等机制，靠自建服务端排行 |
| iOS 内购 | 基本不可用 | 同样受苹果政策限制 |

**主包 20MB 是抖音最大的工程优势**：很多在微信要拆得很碎的项目，
在抖音可以直接进主包，构建配置能简化不少。

## 增长逻辑差异（决定技术取舍）

微信靠**分享裂变**，所以要把分享卡片、群排行、好友 PK 做重。
抖音靠**信息流投放 + 视频引流**，所以要做重的是：

* **录屏分享**：玩家高光时刻录屏 → 一键发布到抖音 → 带小游戏挂载入口
* **首屏 3 秒留存**：买量来的用户耐心极低，Loading 必须快、玩法必须立刻能玩
* **归因埋点**：投放需要回传转化事件，接 **转化 API / 巨量引擎归因**

```javascript
// 录屏（抖音特色能力）
const recorder = tt.getGameRecorderManager();
recorder.onStop((res) => {
  // 拿到视频路径，唤起发布器
  tt.shareAppMessage({
    channel: 'video',
    title: '我拿了新纪录',
    extra: { videoPath: res.videoPath, videoTopics: ['小游戏'] },
    success: () => {},
    fail: (e) => console.error('分享失败', e)
  });
});
recorder.start({ duration: 60 });   // 最长 300s
// ... 精彩时刻结束
recorder.stop();
```

## 登录

流程和微信同构，换个前缀：

```javascript
tt.login({
  force: true,
  success: (res) => {
    // code 交给服务端换 openid（服务端调字节的 code2session）
    tt.request({
      url: 'https://api.example.com/login',
      method: 'POST',
      data: { code: res.code },
      success: (r) => saveToken(r.data.token),
      fail: (e) => showRetry()
    });
  },
  fail: (e) => console.error('登录失败', e)
});
```

差异点：抖音的 `anonymousCode`（匿名标识）在**用户未授权时也能拿到**，
可用于游客态数据打通，微信没有对应概念。

## 激励视频广告

```javascript
const ad = tt.createRewardedVideoAd({ adUnitId: 'xxxx' });

ad.onError((err) => {
  // errCode 1004 = 无广告填充，很常见，要有兜底（比如给个小额保底奖励）
  if (err.errCode === 1004) showToast('暂无广告，稍后再试');
});
ad.onClose((res) => {
  if (res && res.isEnded) grantReward();
});

ad.show().catch(() => ad.load().then(() => ad.show()));
```

抖音的广告特性：

* **多次激励**（`multiton`）：支持连续观看拿多倍奖励，是抖音变现的重要玩法
* 填充率和 eCPM 通常好于微信，**广告是抖音小游戏的收入主力**
* 同样要防「重复发奖」：广告实例单例化 + 服务端校验

## 内购

`tt.requestGamePayment`，需要开通虚拟支付。同样受苹果政策约束，
iOS 端一般不可用，主要做安卓内购。发货**必须以服务端回调为准**。

## 构建与发布

```bash
# 1. Cocos 构建（同样是退出码 36 表示成功）
CocosCreator --project . --build "platform=bytedance-mini-game;debug=false"

# 2. 用 tt-ide-cli 上传
npm i -g tt-ide-cli
tma login                                          # 扫码登录，登录态会过期需重扫
tma upload --project-path ./build/bytedance --version 1.0.0 --changelog "发布说明"
tma preview --project-path ./build/bytedance       # 生成预览二维码
```

和微信 `miniprogram-ci` 的差异：**抖音 CLI 是交互式扫码登录**，
不像微信可以用密钥文件做完全无人值守的 CI，这是自动化流水线里的实际痛点
（常见做法是把登录态缓存下来，过期时人工重扫一次）。

## 审核与资质

* 需要**软著 + 游戏版号**（含内购必须有）
* 类目资质要求和微信类似，但抖音对**买量素材**另有一套广告审核
* 审核周期一般比微信短，但改版频繁，要盯官方公告

## 常见坑

| 现象 | 原因 |
|------|------|
| `tt` API 报参数错误 | 抖音和微信同名 API 参数不完全一致，不能无脑替换前缀 |
| 广告 `errCode 1004` 频繁 | 无填充，属正常现象，必须做兜底提示 |
| CI 上传失败提示未登录 | `tma login` 登录态过期，需重新扫码 |
| 录屏无声 / 时长为 0 | 未在用户交互后调用 start，或 duration 设置不当 |
| 老包在抖音极速版表现异常 | 宿主 App 版本差异，需在多端真机验证 |
