# 跨端适配与工程实践

一套代码同时发微信和抖音，核心思路是**核心逻辑平台无关 + 平台差异收口在适配层**。

## 目录约定

```
assets/scripts/
  core/          # 平台无关：玩法、数值、状态机 —— 严禁出现 wx. / tt.
  platform/
    index.ts     # 统一接口 + 运行时选择实现
    wechat.ts    # wx 实现
    douyin.ts    # tt 实现
    web.ts       # 浏览器预览用的 mock 实现
  ui/            # 视图层
```

**最关键的一条纪律：`core/` 里不允许出现任何 `wx.` / `tt.`**。
这样单元测试可以在 Node 里跑，浏览器预览也能用 mock 跑通，不必每次都出包到真机。

## 适配层设计

先定义**能力接口**，而不是照搬某一家的 API：

```typescript
// platform/types.ts
export interface LoginResult { code: string; }

export interface IPlatform {
  readonly name: 'wechat' | 'douyin' | 'web';
  login(): Promise<LoginResult>;
  showRewardedAd(unitId: string): Promise<boolean>;  // true = 完整观看
  setStorage(key: string, val: string): void;
  getStorage(key: string): string | null;
  share(opt: { title: string; imageUrl: string }): void;
}
```

实现时把各家的回调风格统一成 Promise，并**在边界处理错误**：

```typescript
// platform/wechat.ts
export const wechatPlatform: IPlatform = {
  name: 'wechat',

  login() {
    return new Promise((resolve, reject) => {
      wx.login({
        success: (res) => res.code
          ? resolve({ code: res.code })
          : reject(new Error('登录未返回 code')),
        fail: (e) => reject(new Error(`微信登录失败: ${e.errMsg}`)),
      });
    });
  },

  showRewardedAd(unitId) {
    return new Promise((resolve) => {
      const ad = getAdInstance(unitId);       // 单例，见下文
      const onClose = (res) => {
        ad.offClose(onClose);                 // 先解绑，避免重复发奖
        resolve(!!(res && res.isEnded));
      };
      ad.onClose(onClose);
      ad.show().catch(() => ad.load().then(() => ad.show()).catch(() => {
        ad.offClose(onClose);
        resolve(false);                       // 无填充，按未观看处理
      }));
    });
  },
  // ...
};
```

运行时选择实现：

```typescript
// platform/index.ts
function detect(): IPlatform {
  if (typeof tt !== 'undefined' && tt.getSystemInfoSync) return douyinPlatform;
  if (typeof wx !== 'undefined' && wx.getSystemInfoSync) return wechatPlatform;
  return webPlatform;   // 编辑器预览 / 浏览器调试
}
export const platform: IPlatform = detect();
```

**注意检测顺序**：抖音环境里 `wx` 有时也存在（兼容层），所以**先判 `tt`**。

业务侧调用就完全平台无关了：

```typescript
// core/reward.ts —— 没有任何平台字样
import { platform } from '../platform';

export async function watchAdForCoins(amount: number): Promise<boolean> {
  const watched = await platform.showRewardedAd(AD_UNITS.coins);
  if (!watched) return false;
  await api.grantReward('coins', amount);   // 服务端发奖，前端结果仅作 UI 反馈
  return true;

```

## 广告实例单例化（高频事故点）

重复 `createRewardedVideoAd` 会导致 `onClose` 回调叠加，**一次观看发多次奖励**：

```typescript
const adCache = new Map<string, any>();
function getAdInstance(unitId: string) {
  if (!adCache.has(unitId)) {
    adCache.set(unitId, wx.createRewardedVideoAd({ adUnitId: unitId }));
  }
  return adCache.get(unitId);
}
```

## 差异对照速查

| 能力 | 微信 | 抖音 |
|------|------|------|
| 登录 | `wx.login` | `tt.login`（多 `anonymousCode`） |
| 激励广告 | `wx.createRewardedVideoAd` | `tt.createRewardedVideoAd`（支持多次激励） |
| 内购 | `wx.requestMidasPayment` | `tt.requestGamePayment` |
| 存储 | `wx.setStorageSync` | `tt.setStorageSync` |
| 分享 | `wx.shareAppMessage` | `tt.shareAppMessage`（支持 `channel: 'video'`） |
| 录屏 | 有但用得少 | `tt.getGameRecorderManager`，**主推能力** |
| 好友排行 | 开放数据域 | 无，需自建服务端排行榜 |
| 主包上限 | 4MB | 20MB |

## 分包策略

主包只放**到达第一个可交互画面所必需**的东西：

```
主包：引擎核心 + 登录 + Loading + 主界面
分包A：核心玩法（进游戏时加载）
分包B：商店 / 皮肤（首次点开时加载）
分包C：活动（按需，可下线）
CDN：大图、音频、Spine 动画
```

微信的 4MB 限制常常逼着把主界面资源也挪走；抖音 20MB 则宽松很多。
**可以让两端共用分包划分，只是抖音端把部分分包合回主包**——用构建配置区分，而不是改代码。

## 双端 CI 流程

```bash
# 微信
CocosCreator --project . --build "platform=wechatgame;debug=false"
node scripts/upload-wechat.js        # miniprogram-ci，密钥文件，可无人值守

# 抖音
CocosCreator --project . --build "platform=bytedance-mini-game;debug=false"
tma upload --project-path ./build/bytedance --version $VERSION
```

**Cocos CLI 构建成功的退出码是 36 而不是 0**，CI 脚本里判断要写对：

```bash
CocosCreator --project . --build "platform=wechatgame"
code=$?
if [ "$code" -ne 36 ] && [ "$code" -ne 0 ]; then
  echo "构建失败，退出码 $code"; exit 1
fi
```

自动化程度的现实差距：

* **微信**：`miniprogram-ci` 用密钥文件，可以完全无人值守（注意 IP 白名单）
* **抖音**：`tma` 需要扫码登录，登录态过期要人工介入，**难做到全自动**

## 版本与灰度

* 两端都支持**灰度放量**，新版本先放 10% 观察崩溃率和留存
* 客户端要有**强制更新检查**：服务端下发最低版本号，低于则提示重启
* 小游戏没有「热更新」的通用方案（微信有代码包更新机制但受限），
  **配置类改动尽量走服务端下发**，避免为改个数值重新提审

## 测试与调试

| 场景 | 手段 |
|------|------|
| 玩法逻辑 | `core/` 无平台依赖，Node 里跑单测 |
| UI 与交互 | Cocos 编辑器预览（走 `web.ts` mock） |
| 平台 API | 各家开发者工具模拟器 |
| 真实性能 | **必须真机**，尤其中低端安卓和 iOS |
| 线上问题 | 接错误上报（Sentry 等）+ 平台自带监控面板 |

模拟器和真机差异很大，**性能问题只能真机定位**：模拟器跑在桌面 CPU 上，
永远看不出低端机的掉帧。
