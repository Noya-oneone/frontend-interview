# 微信小游戏

全局对象 `wx`，Cocos 构建目标 `wechatgame`。生态最大，规则也最严。

## 运行环境

微信小游戏**不是浏览器**，只提供一个 Canvas 和 `wx` API：

* **没有 DOM / BOM**：`document`、`window`、`localStorage` 都不存在
  （引擎的 adapter 层会 mock 一部分，但不完整，第三方 npm 库经常因此跑不起来）
* **JS 引擎**：iOS 上是 JavaScriptCore，安卓上是 V8。iOS 没有 JIT，**纯 JS 计算比安卓慢**
* **`wx.getStorageSync`** 代替 localStorage，单 key 上限 1MB，总量 10MB

## 包体限制（硬约束）

| 项 | 限制 |
|----|------|
| 主包 | 4MB |
| 单个分包 | 4MB |
| 全部分包总和 | 30MB |
| 本地缓存（用户侧） | 一般 200MB 量级，按 LRU 淘汰 |

超出主包限制**上传直接失败**。所以小游戏的资源策略几乎必然是：
**主包放引擎 + 首屏 → 分包放玩法 → 大资源放 CDN**。

## 登录与鉴权

```javascript
// 1. 前端拿临时 code（5 分钟有效，一次性）
wx.login({
  success: (res) => {
    if (!res.code) { console.error('登录失败', res.errMsg); return; }
    // 2. code 发给自己的服务器
    wx.request({
      url: 'https://api.example.com/login',
      method: 'POST',
      data: { code: res.code },
      success: (r) => { /* 拿到自己签发的 token */ },
      fail: (e) => { /* 弱网重试 */ }
    });
  },
  fail: (e) => { /* 登录态异常 */ }
});
```

**服务端**用 `code` + `appid` + `appsecret` 调 `jscode2session`，换回 `openid` 和 `session_key`。

* `openid`：用户在**当前小游戏**内的唯一标识
* `unionid`：同一微信开放平台账号下**跨应用**的唯一标识（需绑定开放平台）
* **`appsecret` 绝不能出现在前端代码里**，必须在服务端换取

安全要点：不要用前端传来的 `openid` 直接当身份，一定是服务端用 `code` 自己换。

## 支付（虚拟支付）

小游戏内购走 **`wx.requestMidasPayment`**（米大师），不是普通小程序的 `requestPayment`：

* 必须先在后台开通虚拟支付并**完成游戏版号备案**
* iOS 端因苹果政策**长期无法使用虚拟支付**，通常只做安卓内购 + 双端广告变现
* 流程：前端下单 → 服务端向米大师下单 → 前端调起支付 → **服务端接收回调发货**

**发货必须以服务端回调为准**，绝不能用前端支付成功回调发货（可伪造）。

## 广告变现

```javascript
// 激励视频广告（收益最高的形式）
const videoAd = wx.createRewardedVideoAd({ adUnitId: 'adunit-xxx' });

videoAd.onError((err) => { console.error('广告出错', err); });
videoAd.onClose((res) => {
  // isEnded 为 true 才算完整观看，才发奖励
  if (res && res.isEnded) { grantReward(); }
  else { showToast('看完才能领奖励哦'); }
});

// 展示前必须 load，且要处理无广告填充的情况
videoAd.show().catch(() => videoAd.load().then(() => videoAd.show()));
```

要点：

* 广告实例**全局只创建一次**并复用，重复创建会导致回调重复触发（发多次奖励的经典 bug）
* `onClose` 回调要**先移除再绑定**或用标志位去重
* **发奖励最好也走服务端校验**，前端 `isEnded` 可被篡改

其他形式：Banner（`createBannerAd`）、插屏（`createInterstitialAd`）、原生模板。

## 社交与分享

```javascript
// 主动分享
wx.shareAppMessage({
  title: '快来一起玩',
  imageUrl: 'https://cdn.example.com/share.png',  // 5:4 比例
  query: 'inviteId=123'   // 好友点进来能拿到，做邀请归因
});

// 右上角菜单转发
wx.showShareMenu({ withShareTicket: true });
wx.onShareAppMessage(() => ({ title: '...', imageUrl: '...' }));
```

**开放数据域（Open Data Context）**：好友排行榜的数据受隐私保护，
只能在一个独立的**子域**里渲染，主域拿不到好友信息，只能通过
`wx.getOpenDataContext().postMessage()` 通信，渲染结果以 `sharedCanvas` 贴回主域。
这是微信特有的架构，也是面试常问点。

## 构建与发布

```bash
# 1. Cocos CLI 构建（退出码 36 表示成功，不是 0 —— 这是 Cocos 的历史坑）
CocosCreator --project . --build "platform=wechatgame;debug=false"

# 2. miniprogram-ci 上传
npm i miniprogram-ci
```

```javascript
const ci = require('miniprogram-ci');
const project = new ci.Project({
  appid: 'wx...',
  type: 'miniGame',                 // 小游戏必须是 miniGame，不是 miniProgram
  projectPath: './build/wechatgame',
  privateKeyPath: './private.key',  // 从后台下载，不要提交进仓库
});
await ci.upload({ project, version: '1.0.0', desc: '发布说明' });
```

发布流程注意：

* **上传密钥的 IP 白名单**：CI 机器 IP 要加进后台白名单，否则报 `invalid ip`
* 上传的是**体验版**，需要在后台手动「提交审核」→ 审核通过 →「发布」
* 支持**灰度发布**（按百分比放量），线上出问题可以快速回退到上一版

## 常见坑

| 现象 | 原因 |
|------|------|
| 第三方 npm 库报 `document is not defined` | 无 DOM，需要 polyfill 或换库 |
| 主包超 4M 上传失败 | 资源没分包/没上 CDN |
| iOS 卡顿明显重于安卓 | JSC 无 JIT，减少每帧 JS 计算 |
| 激励视频发多次奖励 | 广告实例重复创建或回调未去重 |
| 贴图白块 | 资源被错误 release |
| `wx.request` 域名报错 | 后台没配置 request 合法域名（且必须 HTTPS） |
