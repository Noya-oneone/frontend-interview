# 清除浮动

## 问题由来

子元素浮动后`脱离文档流`，父元素若没有设置高度，就无法被浮动子元素撑开 —— 出现`高度塌陷`，后续元素还会环绕浮动元素。「清除浮动」就是让父元素恢复正确高度、切断浮动对后续内容的影响。

## 方案对比

| 方案 | 写法 | 评价 |
|--|--|--|
| **clearfix 伪元素**（主流推荐） | 见下方代码 | 无多余标签、无副作用 |
| **父元素触发 BFC** | `overflow: hidden/auto` 或 `display: flow-root` | `flow-root` 专为此而生、零副作用；`overflow` 可能裁掉阴影/弹层 |
| **末尾加空标签** | `<div style="clear: both"></div>` | 有效但污染 HTML，淘汰写法 |
| **父元素定高** | `height: 300px` | 失去自适应，基本不可用 |
| **父元素也浮动** | `float: left` | 问题向上转移（父级的父级又塌陷），且 `margin: 0 auto` 居中失效 |

```css
/* clearfix：给浮动元素的父容器加这个类 */
.clearfix::after {
  content: "";
  display: table;   /* 或 block */
  clear: both;
}
```

```css
/* 现代首选：一行触发 BFC，语义就是“建立新的块级格式化上下文” */
.parent { display: flow-root; }
```

## 原理

* `clear: both`：该元素的盒子必须出现在前面所有浮动盒子`之下`，从而把父元素高度撑到浮动元素底部。
* BFC 方案：`计算 BFC 的高度时，浮动子元素也参与计算`（详见 [BFC](../0-HTML/1-BFC、盒模型（flex&grid）.md)）。

## 常见考点

* **`clear` 加在谁身上？** 加在受影响的`块级元素`上（或父元素的 ::after 伪元素上），对浮动元素本身设置无意义。
* **现在还需要清除浮动吗？** 布局已被 flex/grid 取代，float 回归本职（文字环绕图片）；clearfix 主要出现在维护老代码和面试题里。
