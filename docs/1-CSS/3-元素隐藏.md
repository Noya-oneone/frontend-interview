# 元素隐藏

## 方案对比（高频考点）

| 方案 | 占据空间 | 可点击/交互 | 屏幕阅读器可读 | 触发回流 | 支持过渡动画 |
|--|--|--|--|--|--|
| `display: none` | ❌ 完全移出文档流 | ❌ | ❌ | ✅ 切换时回流 | ❌（配合 `transition-behavior: allow-discrete` 的新特性除外） |
| `visibility: hidden` | ✅ 保留占位 | ❌ | ❌ | 仅重绘 | ✅（离散过渡） |
| `opacity: 0` | ✅ 保留占位 | ✅ **仍可点击**（常见坑） | ✅ 仍会被朗读 | 仅合成 | ✅ 平滑过渡 |
| `position: absolute; left: -9999px` | ❌ 移出视口 | ❌（不在视口内） | ✅ | ✅ | ❌ |
| `clip-path: inset(100%)` | ✅ 保留占位 | ❌ | 视实现而定 | 仅重绘/合成 | ✅ |
| `transform: scale(0)` | ✅ 保留占位 | ❌（无可命中区域） | ✅ | 仅合成 | ✅ 适合动画 |
| HTML `hidden` 属性 | ❌（等效 `display:none`） | ❌ | ❌ | ✅ | ❌ |

## 关键差异说明

* **`display: none`**：元素从渲染树中移除，`不占空间`；子元素无法通过任何方式显示回来；`el.offsetWidth` 读到 0。
* **`visibility: hidden`**：保留占位但不可见不可点；`子元素可以设置 visibility: visible 单独显示`（visibility 可被子级反转，display 不能）。
* **`opacity: 0`**：只是完全透明，`事件照常触发` —— 做「隐藏」时记得配 `pointer-events: none`，否则会出现「点到看不见的按钮」的 bug；反过来这也是自定义文件上传按钮的实现手法（透明 input 覆盖在样式按钮上）。
* **屏幕外定位 / clip-path**：视觉隐藏但保留给屏幕阅读器，是无障碍领域 `sr-only` 工具类的实现思路。

```css
/* 常见的 sr-only：只对屏幕阅读器可见 */
.sr-only {
  position: absolute;
  width: 1px; height: 1px;
  clip-path: inset(50%);
  overflow: hidden;
  white-space: nowrap;
}
```

## 常见考点

* **`display: none` 和 `visibility: hidden` 的区别？** 占位与否、回流 vs 重绘、子元素能否反转、事件都不触发这几点答全。
* **想做淡出后彻底隐藏怎么办？** `opacity` 过渡 + `transitionend` 后再设 `display: none`；或纯 CSS 用 `visibility` 参与 transition（visibility 支持延迟切换）。
* **`display: none` 的元素会加载图片吗？** 会请求 `<img src>`（DOM 存在就加载）；但其 `background-image` 多数浏览器不加载。
