# 响应式布局 & 自适应布局

## 概念区分（高频考点）

| | 响应式（Responsive） | 自适应（Adaptive） |
|--|--|--|
| 思路 | `一套流动布局`，随视口连续变化 | `多套固定布局`，按设备/断点挑一套 |
| 手段 | 媒体查询 + 相对单位 + 弹性布局 | 设备检测（UA / 屏宽），条件加载不同模板或样式表 |
| 变化方式 | 拖动窗口时布局`平滑重排` | 跨过断点时`整体切换`，断点之间不变 |
| 维护成本 | 一套代码 | 多套模板（如 m.example.com 独立移动站） |
| 典型场景 | 现代网站默认做法 | 老牌大型站点的 PC / 移动分站 |

一句话：响应式是「一套布局适应所有设备」，自适应是「为每类设备各做一套」。

## 相对单位：rem vs em

* **rem**：始终相对`根元素 <html>` 的字体大小。`html { font-size: 16px }` 时 `1rem = 16px`。
* **em**：相对`当前上下文`的字体大小 —— 用在 `font-size` 上时参照`父元素`，用在 padding/width 等其他属性上时参照`自身`的 font-size；嵌套时会逐层复利放大，这是它难控的原因。

## 经典移动端适配：rem + 媒体查询

```css
html { font-size: 16px; }

@media (max-width: 600px)  { html { font-size: 14px; } }
@media (min-width: 1200px) { html { font-size: 18px; } }

/* 所有尺寸用 rem 写，根字号一变全局等比缩放 */
h1        { font-size: 2rem; }
.container { padding: 1.5rem; }
.button    { width: 10rem; height: 3rem; }
```

工程上常配 `postcss-pxtorem` 自动把设计稿 px 转 rem；老方案 flexible.js 用 JS 按屏宽设置根字号，现已被 vw 方案取代。

## 现代方案：vw + clamp

```css
/* 根字号随视口宽度流动，但锁定上下限：手机不小于 14px，大屏不超过 20px */
html { font-size: clamp(14px, 1.25vw + 10px, 20px); }

/* 卡片流式栅格：无需任何媒体查询的响应式 */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
  gap: 16px;
}
```

## 常见考点

* **移动端适配做过哪些方案？** 按演进答：媒体查询断点 → rem（flexible.js / pxtorem）→ vw/vh → `clamp()` + 现代布局（grid/flex 本身就是响应的）。
* **为什么 rem 方案要禁用系统字体缩放影响？** 部分浏览器用户调大字号会改变根字号基准；也有人把 `html { font-size: 62.5% }`（=10px）方便换算，但会受用户偏好影响，需权衡无障碍。
* **响应式必须写的 meta？** `<meta name="viewport" content="width=device-width, initial-scale=1">`，否则移动端按 980px 虚拟视口渲染（见 [meta](../0-HTML/<meta>.md)）。
