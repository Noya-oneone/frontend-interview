# 边距重叠（Margin Collapse）

## 核心概念

`同一 BFC 内、常规流中的块级元素`，**垂直方向**相邻的 margin 会合并成一个 —— 这不是 bug，是 CSS 为段落排版设计的规则。水平 margin 永远不合并；flex / grid / 浮动 / 绝对定位的元素不参与合并。

## 三种发生场景

| 场景 | 描述 |
|--|--|
| **相邻兄弟** | 上元素的 `margin-bottom` 与下元素的 `margin-top` 合并 |
| **父子（首/尾）** | 父元素与第一个子元素的 `margin-top` 合并「穿透」到父级外面；与最后一个子元素的 `margin-bottom` 同理。条件：父子之间没有 border、padding、行内内容隔开 |
| **空块元素自身** | 无内容、无 border/padding、无高度的元素，自己的 `margin-top` 和 `margin-bottom` 也会合并 |

## 合并后的值怎么算

* 都为正：取`较大值`（20px + 30px → 30px）
* 一正一负：`相加`（30px + (-10px) → 20px）
* 都为负：取`绝对值较大者`（-20px 和 -30px → -30px）

## 解决方案

| 方案 | 适用场景 | 原理 |
|--|--|--|
| 父元素加 `padding` 或 `border` | 父子穿透 | 隔断了父子 margin 的相邻关系 |
| 父元素 `display: flow-root`（或 `overflow: hidden`） | 父子穿透 | 父元素成为新 BFC，`不同 BFC 的 margin 不合并` |
| 改用 `padding` 拉开间距 | 兄弟合并 | padding 不参与合并 |
| 改用 flex / grid + `gap` | 兄弟合并 | 弹性/网格项目间 margin 不合并，`gap` 更可控 |
| 只从单侧给 margin（如统一只写 `margin-bottom`） | 工程约定 | 从根上避免两个方向的 margin 相遇 |

```html
<!-- 父子穿透示例：子元素的 margin-top 把整个父元素顶下来了 -->
<div class="parent">
  <div class="child">child (margin-top: 20px)</div>
</div>
<style>
  .parent { background: #eee; display: flow-root; } /* 加这行修复 */
  .child  { margin-top: 20px; }
</style>
```

## 常见考点

* **为什么子元素的 `margin-top` 会把父元素顶下来？** 父子 margin 合并穿透 —— 父元素没有 border/padding 隔开时，子元素的上外边距与父元素的上外边距合并，作用到父元素外部。
* **flex 容器里还有 margin 合并吗？** 没有，flex/grid 项目彼此的 margin 不合并（这也是它们「现代好用」的原因之一）。
* **两个 20px 的 margin 合并后是 40 还是 20？** 20 —— 取较大值而非相加。
