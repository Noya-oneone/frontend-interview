# 视口单位（vw / vh / vmin / vmax）

## 定义

| 单位 | 含义 |
|--|--|
| `1vw` | 视口`宽度`的 1% |
| `1vh` | 视口`高度`的 1% |
| `1vmin` | 视口宽高中`较小值`的 1% |
| `1vmax` | 视口宽高中`较大值`的 1% |

竖屏手机（375×812）：`1vmin = 3.75px`（跟宽），`1vmax = 8.12px`（跟高）；横过来两者互换 —— vmin/vmax `不随屏幕方向翻转而改变含义`，这是它们的价值。

## 典型用法

```css
/* 永远完整显示在屏幕内的正方形（不论横竖屏） */
.square { width: 90vmin; height: 90vmin; }

/* 全屏铺满的背景区块 */
.hero { width: 100vw; min-height: 100vh; }

/* 随视口流动但有上下限的标题字号 */
h1 { font-size: clamp(20px, 4vw, 40px); }
```

## 移动端的坑：100vh 与动态视口单位

移动浏览器的地址栏会收起/展开，`100vh` 按`最大视口`计算，导致地址栏展开时底部内容被遮挡。新单位解决了这个问题：

| 单位族 | 基准 |
|--|--|
| `svh / svw` | small viewport：地址栏`展开`时的小视口 |
| `lvh / lvw` | large viewport：地址栏`收起`时的大视口 |
| `dvh / dvw` | dynamic viewport：`跟随地址栏实时变化`（首选，但频繁变化有性能开销） |

```css
.fullscreen { height: 100dvh; }   /* 移动端全屏容器的现代写法 */
```

## 常见考点

* **vw 和 % 的区别？** `%` 相对`父元素`对应尺寸，`vw` 相对`视口`，与嵌套层级无关。
* **100vw 出现横向滚动条？** `100vw` 包含纵向滚动条宽度，页面有滚动条时 100vw > 可用宽度；用 `width: 100%` 或 `max-width: 100vw` + `overflow-x: hidden` 规避。
* **vmin 的适用场景？** 需要元素在横竖屏下都完整可见（大屏海报、二维码、游戏画布）。
