# link VS @import

| 特性 | `<link>` | `@import` |
|--|--|--|
| **本质** | HTML 标签，写在 `<head>` 中 | CSS 规则，只能写在样式表`最顶部` |
| **加载时机** | 随 HTML 解析`并行下载`多个样式表 | 宿主 CSS `下载解析后`才发现并加载，形成`串行瀑布`，拖慢首屏 |
| **能力范围** | 不止 CSS：favicon、preload、prefetch 等 | 只能引入样式表（可带媒体查询条件 `@import url(a.css) print;`） |
| **JS 可操作** | 可通过 DOM 创建/移除（动态换肤、按需加载） | 不可被 DOM 操作 |
| **兼容性** | 全部浏览器 | CSS2.1 起支持（IE5.5+），现代浏览器无兼容问题 |
| **推荐度** | ✅ 生产环境标准做法 | ⚠️ 性能劣势明显，避免在页面里使用 |

## 为什么 @import 慢

```css
/* main.css */
@import url("theme.css");   /* 浏览器必须先下载完 main.css，
                               解析后才知道还要下 theme.css —— 串行两轮 RTT */
```

而两个 `<link>` 是并行下载的。构建工具（Sass 的 `@use`、打包器）会在`编译期`把导入内容合并，产物中不残留运行时 `@import`，所以「源码里写 import、产物里没有」才是正确姿势。

## 常见考点

* **优先级有区别吗？** 没有本质区别 —— 都按 CSS 级联规则，`@import` 的内容视为插入在宿主文件顶部，可能被同文件后面的同权重规则覆盖。
* **@import 为什么必须写在最前面？** CSS 规范要求它出现在除 `@charset` 外所有规则之前，否则被忽略。
* **动态加载 CSS 怎么做？** `document.createElement('link')` 插入 head，监听 `load` 事件确认生效。
