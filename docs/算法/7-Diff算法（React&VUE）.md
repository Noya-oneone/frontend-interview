## React Diff算法

* `React 16 之前`:  `递归算法`进行 Diff 操作，递归调用是同步的，并且不能被中断。这意味着，如果有大量的组件需要更新，浏览器的主线程可能会被长时间占用，从而导致界面卡顿。
* `React 16`: React 采用 Fiber 架构的原因是 `JavaScript 的运行会阻塞页面的渲染`，React 为了不阻塞页面的渲染，采用了 Fiber 架构
* Fiber: React 能够将渲染工作分成可中断和可恢复的单元。这些单元称为“fiber”
* Fiber 本质上是一个虚**拟堆栈帧**，每个 Fiber 对象对应一个 React 组件的实例，并保存了该组件的类型、状态、属性等信息。
* Fiber 其实是一个`链表`的结构，Fiber 是一个链表结构，子节点之间通过 `sibling 指针`连接
* 基于这个数据结构可以实现由原来不可中断的更新过程变成`异步的可中断的更新`。
* 但是由于`没有设置反向指针`，因此没有使用双端比对的方式去优化 Diff 算法
* 没有反向指针，从`右往左遍历链表会很困难`


* Fiber 的工作流程主要分为两个阶段：**Reconciliation（协调）阶段和 Commit（提交）**阶段。
  * `Reconciliation 阶段`：在这个阶段，React 会通过 diff 算法比较新旧两棵 Fiber 树，找出需要更新的节点。这个阶段可以被打断，如果有更高优先级的任务（如用户交互）发生，React 可以暂停当前的渲染任务，**先去执行更高优先级的任务**。
  * `Commit 阶段`：在这个阶段，React 会将 Reconciliation 阶段找出的需要更新的节点应用到 DOM 上。**这个阶段不能被打断**，一旦开始就必须执行到完。


## Vue2 Diff算法

* 采用了`双端 Diff 算法`： 在diff比较的过程中,循环从两边向中间比较
* 对比`头头、尾尾、头尾、尾头`是否可以复用，如果可以复用，就进行节点的`更新或移动操作`。
* 如果经过四个端点的比较，都没有可复用的节点，则将就的子序列保存为节点 key 为 key ，index 为 value 的 map 。
* 拿新的一组子节点的头部节点去 map 中查找，如果找到`可复用的节点，则将相应的节点进行更新，并将其移动到头部，然后头部指针右移`。
* 然而，拿新的一组子节点中的头部节点去旧的一组子节点中寻找可复用的节点，并非总能找到，这说明这个新的头部节点是新增节点，只需要将其挂载到头部即可。
* 经过上述处理，最后还剩下新的节点就批量新增，剩下旧的节点就批量删除。
* `Vue diff 算法` - 使用`双向链表和缓存`来优化比较过程

* **同层级比较**：Vue 的 diff 算法**只会在同一层级进行比较**，不会跨层级比较。
  这是因为跨层级比较的复杂度是 O(n^3)，而同层级比较的复杂度是 O(n)。
* **节点比较**：在比较两个节点时，Vue 首先会比较它们的类型。如果类型不同，Vue 会直接销毁旧节点，创建新节点。如果类型相同，Vue 会复用旧节点，并更新其属性。
* **列表比较**：在比较列表时，Vue 使用了一种叫做 "**就地复用**" 的策略。Vue 会为每个节点生成一个 key，然后通过新旧列表的 key 进行比较，找出需要更新、移动、删除或创建的节点。这个过程通过一个**双指针**的技巧实现，可以在 O(n) 的复杂度下完成。

## vue3 diff算法

* 采用`双端 Diff 算法`
* 对比`头头、尾尾、头尾、尾头`是否可以复用，如果可以复用，就进行节点的`更新或移动操作`。
Vue3 的 Diff 算法与 Vue2 的 Diff 算法一样，也会先进行双端比对，只是双端比对的方式不一样。Vue3 的 Diff 算法借鉴了字符串比对时的双端比对方式，即`优先处理可复用的前置元素和后置元素`。

处理前置节点
处理后置节点
新节点有剩余，则挂载剩余的新节点
旧节点有剩余，则卸载剩余的旧节点
乱序情况（新、旧节点都有剩余），则构建最长递增子序列
节点在最长递增子序列中，则该节点不需移动
节点不在最长递增子序列中，则移动该节点

## 算法对比
Vue3 也采用了`双端对比`的方式优化了 Diff 算法，这一点与 Vue2 是类似的。
Vue3 还构造了`最长递增子序列，最大程度降低了 DOM 操作`，而 React 没有使用最长递增子序列来加速 Diff 算法


## 虚拟DOM (Virtual DOM)
* 虚拟DOM（Virtual DOM）是一种编程概念，它是对真实DOM的抽象，是一种数据结构。 
* `抽象表示`: 在内存中创建一个虚拟的 DOM 树，与实际的 DOM 树进行对比。
* `简化开发`: 提供了一种声明式的方式来描述 UI 结构和状态，简化开发流程
* 减少实际 DOM 操作次数，通过 diff 算法提升性能


## DOM碎片（DocumentFragment）
* DOM碎片（DocumentFragment）在DOM操作中是一种用于提高性能的技术。
* 定义：DocumentFragment是一种`轻量级的文档对象`，
* 它可以包含节点和子节点，但它本身不是一个真实的DOM节点，不会出现在DOM树中，也不会在浏览器页面上渲染显示。
* 创建方式：在JavaScript中，可以通过document.createDocumentFragment()方法创建一个空的DocumentFragment对象。

* `减少DOM操作`：DocumentFragment允许开发者在内存中构建DOM结构，而不是直接在文档中进行。这样可以显著减少页面上的DOM操作次数，尤其是当需要添加、删除或修改大量元素时。
* `减少重绘和重排`：由于DocumentFragment不是DOM树的一部分，因此对其进行的任何操作都不会触发浏览器的重绘（repaint）和重排（reflow）。这些操作只会在DocumentFragment被添加到DOM树时触发一次，从而提高了页面渲染的效率。
* `简化DOM操作`：
使用DocumentFragment可以更方便地在内存中构建复杂的DOM结构，然后再一次性地将其添加到文档中。这样做不仅可以减少DOM操作的次数，还可以使代码更加清晰和易于管理。
* 当需要`动态地向页面添加大量元素时`，可以使用DocumentFragment来构建这些元素的DOM结构，然后再一次性地将它们添加到文档中。
* 在使用前端框架（如Vue、React等）进行开发时，这些框架内部可能会`使用DocumentFragment来优化DOM的更新过程`。
* 虽然DocumentFragment可以提高DOM操作的性能，但在某些情况下（如仅`添加少量元素时`），直接使用DOM方法可能更为简单和高效。
* 在将`DocumentFragment添加到DOM树之前，它不会出现在DOM树中`，也不会被渲染到页面上。因此，在添加之前`无法直接通过DOM选择器访问其中的元素`。


## 总结

### 共同点
* 都是JS框架，都是组件化、天然分层-代码易读（MVC、MVVM），都有自己的生态圈（脚手架、插件、组件库、工具库、社区）
* 都解决频繁操作DOM性能低下问题（虚拟DOM节点问题）


### 区别
* REACT: `函数式编程思想` （JSX、Hooks）：React 更接近于 View 层，只负责 UI 渲染， 把组件设计成纯组件，状态和逻辑通过参数传入，所以在react 中，是单向数据流
* VUE: `响应式`， MVVM（Model-View-ViewModel） 数据是可变的，通过每一个属性建立Watcher 监听，当属性变化时，响应式的更新对应的虚拟DOM

### 适用场景
* 1. `vue 适合 webapp，适合做用户交互多、各种动态效果变化丰富的应用`。特别是PC、手机的网页版 商城等页面。
　　　　原因： vue 实现逻辑复杂的功能比较简单，跟写js似的，而且一些效果、过度感觉很舒服。社区这部分资源也比较多

* 2. `react 适合 oa系统，适合 大批量的数据展示、适合做大型应用`。特别适合公司的后台操作系统。
　　　　原因： react 对那种比较复杂的交互，实施起来比较麻烦，没有vue那么方便。再就是他的渲染原理是渲染整个组件树(除非你做详细设置),所以，一方面费性能，而且代码写起来，逻辑很复杂。但是`react对批量数据操作很厉害`。

* 3. 涉及到混合开发，我个人觉得看情况。
  * 纯H5的混合， 用 reactNative ；
  * 如果50%左右那种，vue+react都可以，具体情况分析吧；
  * 10%那种，啥也别用了，直接html+js接入页面。

* 4. `项目要求的比较高的项目适合用react`。 因为react的社区更活跃一些，尤其是各种UI框架比较稳定、系统，可以信赖。Vue的社区也很活跃，相对来说各种组件五花八门，大多数不够完善、缺乏系统性和迭代。对于项目的后期维护或者新人入手都不友好。
* 5.  从应用上看。`react打出来的包会大一些`，相对来说，Vue打出来的包小一些。如果项目场景对加载速度有要求，建议用Vue
