# 门面模式

## 定义

* 门面模式（Facade Pattern）是一种`结构型设计模式`，它为子系统中的一组接口提供一个`统一的入口`。
* 外观模式`提供了一个简单的接口`，使得子系统更容易使用。


## 场景

* 当一个系统的复杂性增加时，可以考虑使用门面模式来简化其接口。
* 当一个系统的`子系统之间存在很大的依赖关系`时，可以考虑使用门面模式来简化其接口。
* 当一个系统的`子系统需要定制化时`，可以考虑使用门面模式来提供定制化的接口。

* 示例：Vue.js中的全局API
在前端框架中，Vue.js 提供了一个全局的 Vue API，这可以看作是对其内部复杂功能的一个门面。开发者可以通过这些全局API（如`Vue.set, Vue.delete, Vue.nextTick`等）轻松地进行一些操作，而`不需要了解底层的实现细节`。
* 跨平台应用开发：在开发跨平台应用时，不同平台可能有不同的API和操作方式。通过门面模式，可以创建一个`统一的接口封装平台`特定的实现，简化跨平台应用的开发。
* ERP系统中的统一数据访问： 在一个ERP系统中，不同模块（如财务、人力资源、供应链等）可能使用不同的数据源或数据库。通过门面模式，可以为各模块提供一个统一的数据访问接口，使得客户端只需通过这个接口访问数据，而不需要了解底层的数据实现

## 优点

1. 简化了接口，使得客户端使用子系统更加容易。
2. 简化了系统的依赖关系，使得子系统更易于使用和修改。
3. 实现了定制化，使得子系统可以根据需要进行定制。


## 缺点

1. 过多的使用门面模式会增加系统的复杂性。
2. 门面模式会`违反单一职责原则`，因为它为子系统中的一组接口提供了一个统一的入口，这可能会`导致系统的某些功能无法实现`。


## 实现方式

1. `定义一个接口`，该接口包含子系统中`所有需要提供的功能`。
2. 实现该接口，并在该`接口中调用子系统中的相关功能`。
3. 客户端通过该接口调用子系统的功能。


## 实例

```js
// 子系统1
class SubSystem1 {
  method1() {
    console.log('子系统1的method1()');
  }
  method2() {
    console.log('子系统1的method2()');
  }
}

// 子系统2
class SubSystem2 {
  method1() {
    console.log('子系统2的method1()');
  }
  method3() {
    console.log('子系统2的method3()');
  }
}


// 门面
class Facade {
  constructor() {
    this.subSystem1 = new SubSystem1();
    this.subSystem2 = new SubSystem2();
  }

  method1() {
    this.subSystem1.method1();
    this.subSystem2.method1();
  }

  method2() {
    this.subSystem1.method2();
  }

  method3() {
    this.subSystem2.method3();
  }
}


// 客户端
const facade = new Facade();
facade.method1(); // 子系统1的method1() 子系统2的method1()
facade.method2(); // 子系统1的method2()
facade.method3(); // 子系统2的method3()
```


## 总结

门面模式是一种结构型设计模式，它为子系统中的一组接口提供一个统一的入口，使得客户端使用子系统更加容易。它可以简化子系统的接口，实现定制化，并减少系统的复杂性。但是，过多的使用门面模式会增加系统的复杂性，并违反单一职责原则。因此，在设计系统时，需要根据实际情况选择适当的设计模式。
