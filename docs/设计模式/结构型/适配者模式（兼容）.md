# 适配器模式

* 适配器模式（Adapter Pattern）是结构型设计模式
* 它可以将一个类的接口转换成客户希望的另一个接口。
* 适配器模式使得原本由于接口不兼容而不能一起工作的那些类可以一起工作。
* 适配器模式允许`不兼容的接口之间的协作`，使得原本因接口不匹配而不能一起工作的类能够合作。
* 一种数据结构改成另一种数据结构，比如将数组转换成链表。
* 一个接口转换成客户端期望的另一个接口

## 适用场景

* 希望复用一个类，但是其接口与其他类不兼容。
* 想要建立一个可以重复使用的类，该类可以与其他不相关的类或不可预见的类协同工作。
* 想要使用一些已经存在的类，但是其接口不符合你的要求。

* `第三方库集成`：在应用中集成第三方库时，可能需要`将库的接口适配为应用中的接口`。适配器模式可以将第三方库的接口适配为应用需要的接口，方便与系统中的其他部分协作。
* `不同数据库接口`：在一个系统中使用不同的数据库时，可以使用适配器模式将不同数据库的操作接口统一为系统中的通用接口，从而实现对不同数据库的统一操作。
* `老旧系统与新系统集成`：在将老旧系统与新系统集成时，`老旧系统的接口可能与新系统的不兼容`。适配器模式可以`帮助将老旧系统的接口适配为新系统需要的接口，从而实现两者的无缝集成`。

## 优点：

* `解决接口不兼容`：通过适配器，将不兼容的接口适配为客户端期望的接口。
* `提高系统灵活性`：可以将已有的代码和类库无缝地集成到新的系统中。
* `遵循开闭原则`：可以在不修改现有代码的情况下，引入新的适配器，扩展系统功能。

## 缺点：

* `增加系统复杂性`：增加了额外的适配器类，可能会使系统变得更加复杂。
* `潜在性能开销`：在某些情况下，适配器可能引入额外的性能开销，尤其是对于频繁调用的情况。

## js实现

```js
class Dog {
  constructor(name) {
    this.name = name;
  }
  bark() {
    console.log(`${this.name} barks.`);
  }
}

class Cat {
  constructor(name) {
    this.name = name;
  }
  meow() {
    console.log(`${this.name} meows.`);
  }
}

class DogAdapter {
  constructor(dog) {
    this.dog = dog;
  }
  bark() {
    return this.dog.bark();
  }
}

class CatAdapter {
  constructor(cat) {
    this.cat = cat;
  }
  meow() {
    return this.cat.meow();
  }
}

const dog = new Dog('Buddy');
const cat = new Cat('Whiskers');

const dogAdapter = new DogAdapter(dog);
const catAdapter = new CatAdapter(cat);

dogAdapter.bark(); // Buddy barks.
catAdapter.meow(); // Whiskers meows.
```
