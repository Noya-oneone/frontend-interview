# 享元模式

* 享元模式（Flyweight Pattern）是结构型设计模式之一。
* 它通过共享对象来有效地支持大量细粒度的对象。
* 享元模式将对象的状态分为两类：内蕴状态（intrinsic state）和外蕴状态（extrinsic state）。
    * 内蕴状态是对象内部状态的一部分，享元模式会共享这些状态；
    * 外蕴状态则是对象的上下文相关信息，由客户端管理。通过共享内蕴状态，可以显著减少对象的创建数量，从而节省内存。
* 享元模式是一种优化程序性能的模式, 本质为`减少对象创建的个数`
* https://github.com/MuYunyun/blog/blob/main/BasicSkill/%E8%AE%BE%E8%AE%A1%E6%A8%A1%E5%BC%8F/%E4%BA%AB%E5%85%83%E6%A8%A1%E5%BC%8F.md

## 适用场景
* 当需要`创建大量对象`时，且这些对象之间存在重复的内在数据时。
* 当对象的`内在状态可以共享`，而外在状态可以由客户端管理时。
* 当系统中存在`大量细粒度对象`时，想要优化内存使用时。

* `图形系统`：在图形系统中，可能需要绘制`大量相同类型的图形`（如树、文本等）。享元模式可以用来共享图形的内在属性（如形状、颜色），而将位置和其他外在属性由客户端管理。
* `字符渲染`：在文本编辑器中，可以使用享元模式来`共享字符的字体、大小等内在状态`，而将字符的位置、样式等外在状态由客户端管理。
* `网页中的元素`：在网页渲染中，可能需要大量的类似 HTML 元素（如按钮、图标等）。享元模式可以用来`共享元素的样式和模板，从而减少重复的 DOM 元素创建`。



## 结构

* `享元接口（Flyweight）`：定义享元对象的接口，提供方法来处理外蕴状态。
* `具体享元（ConcreteFlyweight）`：实现享元接口，具体实现共享的内蕴状态。
* `享元工厂（FlyweightFactory）`：管理享元对象的创建和共享，确保享元对象的复用。
* `外蕴状态（Extrinsic State）`：由客户端管理的状态，与享元对象的内在状态分开。
* `客户端（Client）`：使用享元工厂创建和管理享元对象，并通过外蕴状态来控制对象的行为。

## 优点

* 减少内存使用：通过共享对象，可以节省内存，提高系统的运行效率。
* 优化性能：当系统中存在大量细粒度对象时，享元模式可以提高性能。

## 缺点

* 增加复杂度：需要定义享元接口、具体享元、享元工厂、客户端等类，增加了系统的复杂度。
* 客户端必须管理外蕴状态：客户端必须管理外蕴状态，以便控制对象的行为。

## 适用环境

* 系统中存在大量的细粒度对象。
* 对象的内在状态可以共享。
* 对象的外在状态可以由客户端管理。
* 客户端需要创建大量对象，但这些对象之间存在重复的内在数据。

## 代码实现

```js
// 享元接口
class Flyweight {
  constructor(sharedState) {
    this.sharedState = sharedState;
  }

  operation(extrinsicState) {
    console.log(`操作内蕴状态：${this.sharedState}，操作外蕴状态：${extrinsicState}`);
  }
}

// 具体享元
class ConcreteFlyweight extends Flyweight {
  constructor(sharedState) {
    super(sharedState);
  }
}

// 享元工厂
class FlyweightFactory {
  constructor() {
    this.flyweights = {};
  }

  getFlyweight(key) {
    if (!this.flyweights[key]) {
      this.flyweights[key] = new ConcreteFlyweight(key);
    }
    return this.flyweights[key];
  }
}

// 客户端
const factory = new FlyweightFactory();
const a = factory.getFlyweight('a');
const b = factory.getFlyweight('b');

a.operation('x'); // 操作内蕴状态：a，操作外蕴状态：x
b.operation('y'); // 操作内蕴状态：b，操作外蕴状态：y
```
