# 状态模式
* 状态模式（State Pattern）是一种行为型设计模式，用于允许对象在其内部状态改变时改变其行为。
* 状态模式通过将状态的行为封装到具体的状态对象中，使得对象的状态改变不会影响到对象的其它部分。
* 每个状态对象负责处理特定状态下的行为，使得状态转换变得简单且清晰。

状态模式适用于以下场景：

1. 对象的行为依赖于它的状态，并且不同的状态下对象的行为有所不同。
2. 一个操作中含有庞大的多分支的条件语句，且这些条件语句依赖于对象的状态。
3. 对象的行为随着时间的推移而改变。
4. 一个对象需要根据它的内部状态改变它的行为。

* `文档编辑器`：在文档编辑器中，文档可能处于不同的状态（`如编辑、预览、只读等`）。状态模式可以用来管理不同状态下的文档行为（如保存、打印等）。
* `游戏角色`：在游戏中，角色可以处于不同的状态（`如待机、行走、攻击等`）。状态模式可以用来管理角色在不同状态下的行为和响应。
* `工作流管理`：在工作流管理系统中，任务可能经历不同的状态（`如待处理、处理中、已完成等`）。状态模式可以用来管理任务在不同状态下的处理逻辑和状态转换。



## 状态模式结构
1. `Context（上下文）`：定义当前状态，并定义一个接口以允许状态改变。
2. `State（状态）`：定义一个接口以封装与状态相关的行为。
3. `ConcreteState（具体状态）`：实现状态接口，并在具体状态下实现状态相关的行为。

## 优点
1. 封装了转换规则，使得状态转换变得简单。
2. 状态模式可以让状态转换代码与状态对象分离，从而简化了对象状态的管理。
3. 状态模式可以让对象自行决定其下一步的行为，从而简化了对象之间的通信。


## 缺点

* `类数量增加`：每个状态都需要一个具体的状态类，可能导致类的数量增加。
* `复杂的状态转换`：在某些情况下，状态的转换逻辑可能变得复杂。

## js实现
```javascript
class Context {
  constructor(state) {
    this.state = state;
  }

  setState(state) {
    this.state = state;
  }

  request() {
    this.state.handle(this);
  }
}

class State {
  handle(context) {
    console.log('State handle');
  }
}

class ConcreteStateA extends State {
  handle(context) {
    console.log('ConcreteStateA handle');
    context.setState(new ConcreteStateB());
  }
}

class ConcreteStateB extends State {
  handle(context) {
    console.log('ConcreteStateB handle');
    context.setState(new ConcreteStateA());
  }
}

const context = new Context(new ConcreteStateA());
context.request(); // ConcreteStateA handle
context.request(); // ConcreteStateB handle
context.request(); // ConcreteStateA handle
```
