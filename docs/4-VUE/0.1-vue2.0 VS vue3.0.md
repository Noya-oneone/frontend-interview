# Vue2 VS Vue3

## 核心差异一览

| 维度 | Vue 2 | Vue 3 |
|--|--|--|
| 响应式 | `Object.defineProperty`（属性增删、数组索引监听不到） | `Proxy`（全面拦截 + 惰性深层代理），见 [双向数据绑定](./0-双向数据绑定.md) |
| API 风格 | Options API | Options API + `Composition API`（setup） |
| 性能 | — | diff 优化：`静态标记（Patch Flags）`、`静态提升`、`事件监听缓存`；更新只比对动态节点 |
| 体积 | 全量打包 | 模块化 + `tree-shaking`，未用到的 API（如 transition）可被摇掉 |
| TypeScript | 支持有限（this 类型难推导） | 源码用 TS 重写，`类型推导一等公民` |
| 新组件 | — | `Teleport`（传送门）、`Fragment`（多根节点）、`Suspense`（异步依赖） |
| 生命周期 | beforeDestroy / destroyed | 改名 `beforeUnmount / unmounted`，组合式用 onXxx（见 [生命周期钩子](./4-生命周期钩子.md)） |
| 逻辑复用 | mixin（命名冲突、来源不清） | `组合式函数（composables）`，显式导入、来源清晰 |
| v-model | 一个 + `.sync` 修饰符 | 组件可绑定`多个 v-model:xxx` |

## 编译期优化（Vue3「更快」的原因，高频考点）

* `静态提升（hoistStatic）`：纯静态节点提升到渲染函数外，只创建一次，重渲染时直接复用。
* `Patch Flags 静态标记`：编译时给动态节点打标记（文本变？class 变？），diff 时`只检查被标记的部分`，跳过静态内容。
* `Block Tree`：以动态节点为单位收集成扁平数组，更新时无需遍历整棵树。
* `事件监听缓存（cacheHandlers）`：内联事件处理器被缓存，避免每次渲染生成新函数导致子组件无谓更新。

## Composition API vs Options API

* **Options API**：按`选项类型`组织（data/computed/methods/watch 分开写）—— 一个功能的代码散落在各处，组件一大就来回跳。
* **Composition API**：按`功能`组织，相关的状态与逻辑聚在一起；可提取为组合式函数复用（替代 mixin）。见 [compositionAPI](./0-compositionAPI.md)、[setup](./0.3-setup.md)。

## Proxy 相对 defineProperty 的优势（重申）

* 代理`整个对象`而非逐属性定义，初始化无需递归。
* 能拦截`属性新增/删除`、`数组索引与 length 变化`、`in / delete` 操作符。
* 深层对象`访问到才递归代理`（在 getter 中按需 reactive），避免无用的深遍历。

## 常见考点

* **Vue3 为什么不兼容 IE11？** Proxy 无法 polyfill。
* **Fragment 带来什么？** 模板允许多个根节点，减少无意义的包裹 div。
* **Teleport 的场景？** 弹窗/抽屉挂到 body 下，摆脱父级 overflow/z-index 限制。
* **Vue2 迁移 Vue3 的主要破坏点？** filters 移除（用 computed/方法替代）、$children 移除、事件总线（$on/$off）移除（用 mitt）、v-model 变更、生命周期改名。
