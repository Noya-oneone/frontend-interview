# Vue 依赖收集

## 核心思想

「谁在渲染时`读取`了我，我变化时就`通知`谁」—— 读取时收集依赖（track），写入时触发更新（trigger）。

## Vue2：Dep + Watcher

* 每个响应式属性配一个 `Dep` 实例（依赖管理器）。
* `Watcher` 代表一段更新逻辑（组件渲染 Watcher、computed Watcher、watch Watcher）。
* 流程：组件渲染前把当前 Watcher 挂到全局 `Dep.target` → 渲染中读到属性触发 getter → `dep.depend()` 把 Dep.target 收进订阅列表 → 数据变化触发 setter → `dep.notify()` 通知所有 Watcher 更新。
* 因为依赖收集精确到`组件级`，Vue 不需要像 React 那样自上而下重渲染 —— 谁用了谁更新。

## Vue3：effect + targetMap

* 更新逻辑抽象为 `effect`（副作用函数），组件渲染函数就是一个 effect。
* 依赖存储结构（手写响应式必考）：

```
targetMap: WeakMap<原始对象, Map<key, Set<effect>>>
```

```js
let activeEffect = null;
const targetMap = new WeakMap();

function track(target, key) {           // Proxy get 中调用
  if (!activeEffect) return;
  let depsMap = targetMap.get(target) ?? targetMap.set(target, new Map()).get(target);
  let dep = depsMap.get(key) ?? depsMap.set(key, new Set()).get(key);
  dep.add(activeEffect);
}

function trigger(target, key) {         // Proxy set 中调用
  targetMap.get(target)?.get(key)?.forEach((effect) => effect());
}

function effect(fn) {
  activeEffect = fn;
  fn();                                 // 执行期间读到的属性完成收集
  activeEffect = null;
}
```

* 用 `WeakMap` 做外层键：目标对象被回收时依赖记录随之释放，不造成内存泄漏。

## 触发更新之后

通知到的组件`不会立即重渲染`，而是推入`异步更新队列`（去重），在下一个微任务里批量执行 —— 这就是同一轮修改多次数据只渲染一次、以及 [nextTick](./1.2-nextTick.md) 存在的原因。

## 常见考点

* **computed 的依赖收集有何不同？** 它既是订阅者（依赖别的数据）又是发布者（被模板依赖），且带`惰性求值 + 脏标记缓存`（见 [computed](./1.1-computed.md)）。
* **为什么渲染时才收集，而不是初始化时？** 只有真正被渲染用到的数据才值得订阅 —— v-if 隐藏分支里的数据变化不会触发无谓更新。
