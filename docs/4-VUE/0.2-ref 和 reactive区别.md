# VUE的ref和reactive区别

### ref 和 reactive区别

* ref 适用于单个值(创建一个响应式的值)
* reactive 适用于对象。 (创建一个响应式的对象)
* 在模板中，ref 需要通过 .value 访问，而 reactive 可以直接访问。

| 特性       | `ref`                      | `reactive`                |
|------------|----------------------------|---------------------------|
| **适用数据类型** | 基本类型和对象              | 对象和数组                 |
| **访问方式**   | `.value`                   | 直接访问                   |
| **深度响应**   | 对基本类型和对象的 `.value` 进行响应式处理 | 对对象及其` 所有嵌套属性` 进行深度响应 |


## reactive
reactive：用于创建响应式对象，接收一个普通对象作为参数，返回该对象的响应式代理。它不能直接处理基本数据类型（如 number、string、boolean 等）。

* 基于 ES6 的 Proxy 实现响应式。Proxy 可以拦截对象的各种操作（如属性访问、属性赋值、函数调用等），从而实现对对象属性变化的监听和响应。
* 在模板中可以直接访问响应式对象的属性，无需额外操作
* 当对 reactive 对象进行解构时，会失去响应式特性。因为解构会将对象的属性复制到新的变量中，这些变量不再与原响应式对象关联。


## ref
ref：可以用来创建任意类型的响应式数据，既可以处理基本数据类型，也能处理对象、数组等引用类型。创建时需要传入一个初始值，访问和修改其值时需要通过 .value 属性。

* **内部使用 reactive 来实现**，它将传入的值封装在一个带有 value 属性的对象中，然后对这个对象应用 reactive 进行响应式处理。
* 在模板中使用时，不需要显式地通过 .value 访问，Vue 会自动解包 ref。但在 JavaScript 代码中访问和修改值时，仍需要使用 .value
* 可以使用 toRefs 函数将 reactive 对象转换为一组 ref，这样在解构后仍能保持响应式



## 设计两种定义的原因
1. 灵活性
ref 提供了统一的方式来处理基本数据类型和引用类型的响应式数据，开发者无需担心数据类型的差异，可以方便地创建和管理各种类型的响应式数据。
reactive 则专注于处理对象的响应式，对于处理复杂的对象结构和嵌套对象时更加直观和自然。
2. 兼容性和易用性
在模板中，ref 的自动解包特性使得使用基本数据类型的响应式数据更加方便，开发者可以像使用普通变量一样在模板中使用 ref。
reactive 直接操作对象，符合开发者对 JavaScript 对象的常规操作习惯，在处理对象相关逻辑时更加直观。
3. 逻辑复用和代码组织
ref 更适合在逻辑复用和组合函数中使用，因为它可以方便地传递和返回基本数据类型的响应式值。
reactive 则在处理复杂的状态对象和组件状态管理时更具优势，能够清晰地组织和管理对象的属性和状态。



逻辑分组：在使用 Composition API 进行逻辑复用和代码组织时，reactive 可以将相关的状态和逻辑组织在一起，形成一个独立的逻辑单元。例如，在一个表单组件中，将表单的所有字段和验证逻辑封装在一个 reactive 对象中：

```js
import { reactive } from 'vue';
const formData = reactive({
    username: '',
    password: '',
    validate() {
        // 验证逻辑
    }
});
```


解构和传递：reactive 在某些情况下解构和传递更加方便。虽然直接解构 reactive 对象会失去响应式，但可以使用 toRefs 来解决这个问题。而 ref 在传递和处理复杂对象时，可能需要更多的操作来确保响应式的正确传递
```js
import { ref } from 'vue';

const user = ref({
    name: ref('Alice'),
    age: ref(25),
    address: ref({
        city: ref('New York'),
        street: ref('123 Main St')
    })
});
```
