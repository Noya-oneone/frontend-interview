# 数据劫持 & 虚拟DOM

## 数据劫持

### 作用

* `精准检测数据变化`：Vue 通过数据劫持（Vue2 用 `Object.defineProperty`，Vue3 用 `Proxy`）拦截数据的读取和写入 —— 读时`收集依赖`，写时`触发更新`。
* `自动更新视图`：数据变化时自动通知依赖它的组件重渲染，保持视图与数据同步，开发者不必手动操作 DOM。

### Object.defineProperty 的局限（Vue2 痛点，高频考点）

* `监听不到属性的新增与删除`（只能劫持已定义的属性）→ 需要 `Vue.set / Vue.delete`。
* `数组的索引赋值和 length 修改无法拦截` → Vue2 靠重写 push/pop 等 7 个变更方法弥补。
* 初始化时需要`递归遍历整个对象`为每个属性设置 getter/setter，深层大对象开销大。
* Proxy 如何解决这些问题见 [双向数据绑定](./0-双向数据绑定.md)、[vue2.0 VS vue3.0](./0.1-vue2.0%20VS%20vue3.0.md)。

## 虚拟 DOM

### 是什么

用 JS 对象在内存中描述真实 DOM 的轻量副本。数据变化时生成新的虚拟 DOM 树，与旧树 `diff` 比较，只把差异部分`批量更新`到真实 DOM。

### 为什么需要

* `减少真实 DOM 操作`：DOM 操作昂贵（触发回流重绘），diff 后只更新变化部分、多次修改合并为一次提交。
* `声明式编程的基础`：开发者只描述「界面应该长什么样」，框架负责算出最小更新 —— 这才是虚拟 DOM 的核心价值。
* `跨平台能力`：虚拟 DOM 是平台无关的中间层，同一套组件可渲染到浏览器、SSR 字符串、原生（Weex/小程序）。

### 虚拟 DOM 一定更快吗？（高频追问）

不一定。对单次精准的 DOM 修改，直接操作 DOM 更快 —— 虚拟 DOM 多了创建 JS 对象和 diff 的开销。它的价值是`在「不手动优化」的前提下提供不错的默认性能`，属于可维护性与性能的折衷。Vue3 通过编译期优化（静态提升、Patch Flags 靶向更新）大幅缩小了这层开销。

## 常见考点

* **数据劫持和虚拟 DOM 分别解决什么问题？** 前者解决「`何时`更新」（感知数据变化、精确到组件），后者解决「`如何高效`更新」（算出最小 DOM 操作集）。
* **diff 算法的策略？** 同层比较不跨层、类型不同直接替换、列表靠 [key](./key.md) 复用节点（Vue2 双端比较，Vue3 最长递增子序列）。
