# 数据劫持 & 虚拟DOM

## 数据劫持
### 作用
* 精准检测数据变化：Vue 通过数据劫持（使用 Object.defineProperty 或 Proxy）来拦截数据的读取和写入操作。这使得 Vue 能够在数据发生变化时及时触发视图更新。
* 自动更新视图：当数据发生变化时，Vue 能够自动通知组件更新视图，从而保持视图与数据的同步。
### 限制
* 性能开销：对于复杂的组件和大规模的应用，数据劫持可能会引入性能开销。每次数据变化时，Vue 需要更新所有受影响的 DOM 元素。
* 精细化控制困难：直接操作 DOM 可能会带来性能问题，尤其是在需要频繁更新的情况下。对于大规模的变更，直接操作 DOM 可能会导致性能瓶颈。

## 虚拟 DOM
### 作用
* 高效更新视图：虚拟 DOM 是一种在内存中表示实际 DOM 的轻量级副本。Vue 在每次数据变化时，会先创建一个新的虚拟 DOM 树，并将其与之前的虚拟 DOM 树进行比较（diff 算法）。这使得 Vue 能够高效地计算出实际 DOM 中需要更新的部分。
* 最小化实际 DOM 操作：通过 diff 算法和批量更新机制，Vue 只更新实际 DOM 中发生变化的部分，从而减少了对 DOM 的操作次数和开销。
* 支持复杂的 UI 更新：虚拟 DOM 使得 Vue 能够支持复杂的 UI 更新场景，例如组件嵌套、条件渲染和列表渲染等。
### 为什么需要虚拟 DOM
#### 性能优化：

* 减少 DOM 操作：直接操作实际 DOM 性能开销较大。通过虚拟 DOM，Vue 可以批量计算并更新 DOM，从而减少不必要的 DOM 操作，提高性能。
* 高效的 diff 算法：虚拟 DOM 的 diff 算法可以快速计算出实际 DOM 中的差异，并只应用必要的更新，从而优化性能。
复杂 UI 的处理：
* 组件化和动态更新：对于复杂的组件和动态更新的 UI，虚拟 DOM 使得 Vue 可以高效地管理和更新视图，而不需要每次都重新渲染整个 DOM 树。
* 灵活性：虚拟 DOM 提供了一种灵活的方式来处理各种 UI 变更场景，包括条件渲染、列表渲染等。
