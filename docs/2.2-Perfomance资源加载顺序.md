# 流程

# 浏览器输入输入url后，浏览器执行步骤？

1、URL解析: 浏览器的地址栏输入URL并按下回车、。
2、缓存：浏览器查找当前URL是否存在缓存，并比较缓存是否过期。
3、DNS解析：DNS解析URL对应的IP。
4、根据IP建立TCP连接（三次握手）。
5、HTTP发起请求。
6、服务器处理请求，浏览器接收HTTP响应。
7、渲染页面，构建DOM树。
8、关闭TCP连接（四次挥手）

## 页面渲染

* 获取HTML、解析HTML
    * 标记解析：浏览器逐行读取 HTML 标记并构建 DOM 元素。
    * 解析嵌套：处理嵌套的标签和属性，构建父子关系。
* 获取CSS
    * 选择器解析：解析 CSS 选择器和样式规则。
    * 计算样式：根据选择器匹配元素并计算最终的样式。
* 渲染树构建
    * 在解析HTML的过程中，浏览器会遇到link、script等标签、生成DOM，生成CSSOM
    * Composite渲染树合成
* Layout布局
    * 计算宽高：确定每个元素的具体宽度、高度、位置等。
    * 处理流式布局：根据内容和容器的尺寸计算元素的实际布局。
* Paint绘制
    * 绘制内容：将文本、图像、背景颜色等绘制到页面上。
    * 处理图层：合成图层，将绘制的内容合并并显示在屏幕上。
* JS执行
    * 脚本执行：解析并执行脚本，可能会修改 DOM 或 CSSOM。
    * 重新渲染：如果 JavaScript 修改了 DOM 或样式，浏览器可能会重新计算布局和重绘。
* 页面交互
    * 事件处理： 页面加载完成后，用户可以与页面交互，如点击、滚动等，浏览器会处理这些事件并更新页面。

## 静态资源加载顺序
* HTML：优先下载和解析。浏览器在解析 HTML 时构建 DOM 树。
* CSS：在遇到 <link> 标签时下载并解析，阻塞渲染直到 CSS 解析完成。
* JavaScript：在遇到 <script> 标签时处理：
    同步脚本：阻塞 HTML 解析，执行 JavaScript 后继续解析。
    异步脚本：不阻塞 HTML 解析，下载完成后立即执行。
    延迟脚本：不阻塞 HTML 解析，HTML 解析完成后执行。


`重排（Reflow）‌就是回流`  ，是指当DOM的变化影响了元素的几何属性（例如宽度、高度、位置等），浏览器需要重新计算元素的几何属性，并且重新布局页面上的元素。

`重绘（Repaint）`‌则是指当页面中元素样式的改变不影响其在**文档流中的位置**时，浏览器只需要将新的样式应用到元素上并重新绘制它，这个过程称为重绘。更新样式

CSS解析会影响Js执行吗？
CSS 解析通常不会直接影响 JavaScript 的执行
CSS 阻塞渲染：在页面加载过程中，浏览器在下载和解析 CSS 文件时会阻塞页面的渲染。虽然这主要影响页面的渲染性能，但如果 CSS 文件在 <head> 中，它可能会延迟后续 JavaScript 的执行，尤其是在没有 async 或 defer 属性的情况下。
JavaScript 执行顺序：如果 JavaScript 文件在 HTML 中的 <head> 部分，且没有 async 或 defer 属性，浏览器会在 CSS 解析完成之前阻塞 JavaScript 的执行。因此，CSS 解析可能间接影响 JavaScript 的执行时机。


## 性能优化的原则
* 多使用内存，缓存或者其他方法
* 减少CPU计算（优化算法和数据结构，以减少计算复杂度）
* 减少网络请求
* 减少IO-Input/Output操作（包括与磁盘、网络、数据库等的交互）

| 类型| 描述 | 示例|
|---|---|---|
| **磁盘 I/O** | 涉及文件系统的读写操作，如文件的创建、读取、写入和删除。 | 读取配置文件、写入日志文件|
| **网络 I/O** | 涉及网络通信的操作，如发送和接收数据包。 | HTTP 请求/响应、Socket 通信 |
| **数据库 I/O** | 涉及数据库的操作，如查询、插入、更新和删除。 | 执行 SQL 查询、更新数据库记录|
| **设备 I/O** | 涉及硬件设备的操作，如读写硬盘、输入设备、输出设备。 | 从传感器读取数据、向打印机发送数据|
