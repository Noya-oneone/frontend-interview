# webpack构建流程###  **webpack构建流程**

* **初始化：`webpack.config.js`**
* 接收命令行参数和 webpack.config.js 配置文件，合并参数，初始化 `Compiler` 对象。
* **编译**：
* Webpack 开始编译，从入口文件开始，解析模块依赖，形成依赖关系图。
* **转换 `Loader`**：
* 对每个模块进行转换，调用 Loader 对模块源代码进行转换。
* **优化 `Plugin`**：
  * Tapable ，Webpack Plugin 是完全基于它来实现的
  * Tapable 提供了一系列事件的发布订阅 API ，通过 Tapable我们可以`注册事件`，从而在不同时机去触发注册的事件进行执行。
  * 资源处理：可以在资源被处理之前或之后进行自定义处理，例如压缩、转码等。
  * 文件输出：可以在文件输出之前进行修改或添加内容。
  * 编译优化：可以在编译过程中优化生成的代码，例如删除冗余代码、代码分割等
* `9种类型钩子、发布订阅者模式的插件 Plugin 机制`
* 对转换后的模块进行优化，如代码压缩、拆分等。
  * **`UglifyJsPlugin`**：用于压缩 JavaScript 代码，删除无用的代码和注释。
  * **`HtmlWebpackPlugin`**：用于生成 HTML 文件，可以自动引入打包后的 JS 和 CSS 文件。
  * **`MiniCssExtractPlugin`**：用于将 CSS 代码从 JS 文件中提取出来，生成单独的 CSS 文件
  * **`OptimizeCSSAssetsPlugin`**：用于优化和压缩 CSS 代码。
  * **`TerserPlugin`**：用于压缩 ES6 代码。
  * **`CompressionWebpackPlugin`**：用于生成 Gzip 压缩文件，可以减少服务器传输的文件大小。
  * **`SplitChunksPlugin`**：用于代码分割，可以将公共的依赖模块提取到已有的入口 chunk 中，或者提取到新生成的 chunk。
* **`HardSourceWebpackPlugin`**：用于提供中间缓存，可以大大提高重复构建的速度。
* **`DllPlugin 和 DllReferencePlugin`**：用于分离第三方库和应用代码，可以提高构建速度。
* **`CleanWebpackPlugin`**：用于在每次构建前清理 /dist 文件夹。
* `CopyWebpackPlugin`：用于将单个文件或整个目录复制到构建目录。
* Webpack 会将所有的 chunk 进行优化，将大小超过 30KB，被至少一个 chunk 共享的模块，分离出来。并且，Webpack 会将 node_modules 目录下的模块分离到 **vendors** 组，将被至少 2 个 chunk 共享的模块分离到 default 组。
* **输出 `Chunk`**： 分包机制
* `SplitChunksPlugin`
* 根据依赖关系图，生成 **Chunk，再将** Chunk 转换为文件，写入到文件系统。

* **cache-loader 和 hard-source-webpack-plugin 的 区 别**
  * cache-loader 和 hard-source-webpack-plugin 都是用于缓存加载结果以提高 webpack 构建速度的插件，但它们的工作方式和使用场景有所不同。

  * **cache-loader** 是一个普通的 loader，它会缓存其他 loader 的结果。在使用时，需要将 cache-loader 放在其他 loader 之前。

  * **hard-source-webpack-plugin** 是一个插件，它会缓存整个模块的结果，包括模块的依赖关系和 loader 的结果。

* cache-loader 更适合用于缓存耗时的 loader，如 babel-loader、ts-loader 等，而 hard-source-webpack-plugin 更适合用于提高**重复构建的速度**。
