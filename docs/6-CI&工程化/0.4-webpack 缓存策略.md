# Webpack 缓存策略

## 缓存策略概览

| 缓存策略  | 使用场景| Webpack 配置示例  |
|-|----|----|
| **强缓存**| 静态资源（CSS、JS、图片）、构建输出文件、不频繁变动的资源 | 使用 `[contenthash]` 生成唯一文件名 |
| **协商缓存**| 动态生成的资源、经常变动的内容、API 请求| 配置服务器端的 `Cache-Control` 和 `ETag` 头部 |

## Module Caching

Webpack 默认会缓存模块，避免重复解析和构建相同的模块。这种缓存是在内存中进行的，对于模块之间的依赖关系能够快速访问。

## Content Hashing

在输出的文件名中使用内容哈希（[contenthash]）可以确保当文件内容改变时，生成的新文件名也会随之改变，从而利用浏览器缓存，避免用户下载不必要的文件。

* 这意味着，如果文件没有变化，浏览器可以使用之前缓存的文件，而不需要重新请求，减少了网络带宽和加载时间。

## 持久化缓存（Persistent Caching）

### 背景

* webpack 作为一个模块打包工具，在开发过程中，我们经常需要频繁的修改代码，每次修改都需要重新打包，这样效率非常低下。
* 为了提高开发效率，webpack 提供了持久化缓存的功能，可以将打包后的文件缓存到磁盘，下次打包时直接读取缓存文件，避免重复打包。
* 持久化缓存（Persistent Caching）通过缓存构建结果来加快后续构建速度，减少开发者等待时间，当依赖关系相对稳定，且不频繁更改时，持久化缓存能有效提高效率，在生成生产环境构建时，持久化缓存能够帮助快速构建和部署

### 缺点

* 磁盘空间占用：持久化缓存会占用磁盘空间，特别是在大型项目中，缓存数据可能会占用显著的存储。
* 复杂性增加：管理缓存的有效性和过期策略可能增加构建过程的复杂性，需要额外的配置和管理。
* 调试困难：当出现问题时，缓存可能导致构建结果不一致，增加了调试的难度。
* 不适用快速迭代：在频繁更改和快速迭代的开发过程中，可能导致缓存未能及时更新，影响构建结果。

### 开启缓存

webpack 持久化缓存默认是关闭的，需要在配置文件中配置 `cache` 选项开启。

```javascript
module.exports = {
  // ...
  cache: true, // 开启缓存
  // ...
}
```

### 缓存目录

默认情况下，webpack 缓存文件会被存储在 `node_modules/.cache/webpack` 目录下，可以通过 `cacheDirectory` 选项自定义缓存目录。

```javascript
module.exports = {
  // ...
  cache: {
    cacheDirectory: 'path/to/cache/directory',
  },
  // ...
}
```

### 缓存失效

缓存文件默认是永久有效的，如果需要每次打包前都清除缓存，可以设置 `cache.type` 选项为 `filesystem`。

```javascript
module.exports = {
  // ...
  cache: {
    type: 'filesystem'
  },
  // ...
}
```

### 缓存压缩

webpack 缓存文件默认是压缩的，可以通过 `cache.cacheCompression` 选项关闭压缩。

```javascript
module.exports = {
  // ...
  cache: {
    cacheCompression: false
  },
  // ...
}
```

### 缓存版本

webpack 缓存文件默认是基于 webpack 版本的，如果需要每次打包前都清除缓存，可以设置 `cache.version` 选项为 `false`。

```javascript
module.exports = {
  // ...
  cache: {
    version: false
  },
  // ...
}
```

### Webpack 5 内置持久化缓存

Webpack 5 引入了内置的持久化缓存功能，可以配置使用文件系统缓存，增强缓存的灵活性和性能。

## File System Cache

Webpack 可以使用文件系统缓存，将编译结果存储在磁盘上，以便在后续构建中快速访问。这是持久化缓存的一种形式，但可以更灵活地进行配置。

## DLL 插件

使用 Webpack 的 DLL 插件，可以将依赖库单独打包，生成一个 DLL 文件。这样，在开发过程中，只需在主应用中引用 DLL 文件而无需每次都打包依赖库，提高构建速度。

## SplitChunksPlugin

通过代码分割（Code Splitting）技术，Webpack 可以将共享的模块提取到单独的 chunk 中，减少重复打包，从而利用浏览器的缓存。

## Aggressive Splitting

通过配置 aggressive splitting，Webpack 可以将大文件拆分成更小的部分，减少初次加载时间，并提高缓存命中率。

## Hard Source Plugin

hard-source-webpack-plugin 提供了一个中间层的文件系统缓存，用于存储模块的构建结果，减少重新构建的时间。

## Terser Plugin

使用 terser-webpack-plugin 进行代码压缩时，它会缓存压缩后的结果，避免在多次构建中重复压缩相同的代码。

## 总结

Webpack 提供了多种缓存机制，可以结合使用这些方式，根据项目需求优化构建性能。在选择缓存策略时，需考虑项目规模、开发流程和部署环境，以达到最佳效果。
