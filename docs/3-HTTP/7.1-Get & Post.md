# GET 和 POST

HTTP 方法：`GET、POST、PUT、DELETE、PATCH、HEAD、OPTIONS`。

## 核心区别

| 维度 | GET | POST |
|--|--|--|
| **语义** | `读取`资源 | `提交`数据 / 创建资源 |
| **幂等性** | ✅ 幂等（多次执行结果相同），可安全重试 | ❌ 非幂等，重复提交会重复下单 |
| **参数位置** | URL 查询串（受 [URL 长度限制](./URL%20长度问题.md)约 2000 字符） | 请求体，大小几乎不限 |
| **可缓存** | ✅ 可被浏览器/CDN 缓存、可收藏、可留在历史记录 | 默认不缓存 |
| **编码类型** | 仅 URL 编码 | 支持 `application/json`、`multipart/form-data`（文件上传）等 |
| **CORS** | 常为简单请求 | JSON body 会触发预检（见 [跨域问题](./3-跨域问题.md)） |

底层视角：两者`都是 HTTP 报文，本质没有区别`（都跑在 TCP 上），差异全部来自 HTTP 规范约定与浏览器/服务器实现。

## 「GET 一个包、POST 两个包」的说法

* 说法来源：部分浏览器对 POST 先发 header、待服务器回 `100 Continue` 再发 body。
* 实情：这`取决于客户端实现`（Firefox 就只发一次），不是协议规定；正常网络下差异可忽略，不能作为两者的本质区别 —— 面试提到这个说法时应指出它不严谨。

## 安全性辨析（易答错）

* GET 参数暴露在 URL 中：会进入`浏览器历史、服务器访问日志、Referer 头`，还容易被截图分享 —— 敏感数据不要放 URL。
* 但 POST `并不加密`：body 在 HTTP 下同样是明文，抓包一样看得到。真正的传输安全靠 `HTTPS`，POST 只是「不那么显眼」。

## 常见考点

* **为什么 GET 幂等很重要？** 浏览器预取、代理重试、CDN 缓存都建立在「GET 无副作用」的约定上 —— 用 GET 做删除操作曾造成过爬虫误删数据的真实事故。
* **PUT vs POST vs PATCH？** PUT 全量替换（幂等）、PATCH 局部更新、POST 创建/通用提交（非幂等）。
* **GET 能带 body 吗？** 协议未禁止但语义未定义，各代理/服务器行为不一 —— 别用；复杂查询参数考虑 POST 或 GraphQL。
