# 刷新行为与缓存命中

不同刷新方式对 Memory Cache / Disk Cache 的影响（高频考点：为什么 F5 后变成 304、Ctrl+F5 后全是 200）：



| 场景 | 浏览器操作 | Memory Cache | Disk Cache | 网络请求 | 说明 |
|------|------------|-------------|------------|---------|------|
| 普通模式 | 首次访问资源 | ✅ 缓存 | ✅ 缓存 | 发请求 → 200 OK | 视频/资源存入内存和磁盘缓存 |
| 普通模式 | 普通刷新 F5 / Cmd+R | ❌ 清空 | ✅ 保留 | 发验证请求（If-None-Match / If-Modified-Since） → 304 Not Modified | 浏览器使用 Disk Cache，节省带宽 |
| 普通模式 | 强制刷新 Ctrl+F5 / Cmd+Shift+R | ❌ 清空 | ❌ 清空 | 发请求 → 200 OK | 无缓存，重新下载资源 |
| 普通模式 | 关闭浏览器再打开 | ❌ 清空 | ✅ 保留 | 不发网络请求 → 直接使用 Disk Cache | 浏览器检查 Disk Cache，未过期直接命中 |
| 无痕模式 | 首次访问资源 | ✅ 缓存 | ❌ 不缓存 | 发请求 → 200 OK | 只缓存内存，不写磁盘，关闭会话即清除 |
| 无痕模式 | 普通刷新 F5 | ❌ 清空 | ❌ 不缓存 | 发请求 → 200 OK / 304 Not Modified | 每次刷新都需要网络请求，Memory Cache 不持久 |
| Chrome DevTools | 勾选 Disable cache | ❌ 禁用 | ❌ 禁用 | 每次都发请求 | 禁用内存缓存、磁盘缓存和 Service Worker Cache，但 Cookie / LocalStorage / IndexedDB / CDN 不受影响 |
