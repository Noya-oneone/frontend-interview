
# 应用层 - HTTP1.0 & HTTP1.1 & HTTP2.0 区别& HTTP3.0 介绍

## `HTTP 1.0`

<!-- 每个连接只能处理一个请求（请求/响应） -->

* ***短暂连接**：HTTP 1.0 规定浏览器与服务器之间维持短暂的连接，即每次请求都**需要新建一个 TCP 连接**，并在请求完成后立即断开。
**无状态**：服务器不保留任何关于客户端的信息，每次请求都是独立的，服务器不会追踪或记忆客户的请求历史。
**队头阻塞**：由于请求按序进行，一旦前面的请求出现延迟，后面的请求也会被阻塞，导致整体性能下降。

## `HTTP 1.1`

**长连接**：HTTP 1.1 引入了长连接的概念，通过设置 Connection: **keep-alive 字段**，客户端和服务器可以在一次 TCP 连接中发送多个请求和响应，减少了连接建立和关闭的开销。
**管道化**：基于长连接，HTTP 1.1 支持请求管道化，即允许客户端**同时发送多个请求，不必等待前一个响应回来**，从而提高效率。
**缓存控制**：HTTP 1.1 对缓存机制进行了增强，引入了更多缓存相关的响应头字段，如 **Cache-Control**，更好地控制缓存行为。
**分块传输编码**：HTTP 1.1 支持**分块传输编码**，允许服务器在发送响应的同时进行响应内容的生成，提高了响应速度。

## `HTTP 2.0`

<!-- HTTP/2 引入了多路复用，可以在一个 TCP 连接上并发地处理多个请求和响应，从而减少了对并发连接数的需求 -->

**二进制分帧**：HTTP 2.0 使用**二进制格式**对数据进行分帧传输，使得协议解析更为灵活和高效。**HTTP1.0 文本格式**的数据
**头部压缩**：通过引入**头部压缩机制**，减少了不必要的**头部字段重复**，降低了**带宽消耗**。
**多路复用**：HTTP 2.0 允许多个请求和响应在同一个 TCP 连接上并发进行，消除了**队头阻塞问题**，提升了性能。
**服务器推送**：服务器可以主动向客户端推送资源，有助于实现更快的页面加载时间。


## `HTTP 3.0`

<!-- 现代浏览器通过 HTTP/2 或 HTTP/3 来优化连接的使用，减少了对多连接的需求 -->

* **基于 QUIC 协议**：HTTP/3 使用 QUIC（Quick UDP Internet Connections）协议作为传输层协议。QUIC 是一种基于 UDP 的协议，旨在减少延迟并提高数据传输效率。

* **无头部阻塞**：与 HTTP/2 的 TCP 连接不同，QUIC 支持多路复用流而不受头部阻塞（Head-of-Line Blocking）的影响。HTTP/3 可以同时处理多个流，每个流可以独立传输，避免了 HTTP/2 中由于一个流阻塞导致其他流受影响的问题。
* **改进的握手过程**：QUIC 通过集成加密和握手过程，`减少了连接建立的延迟`。HTTP/3 结合了传输层加密（TLS）和连接建立，使得数据加密和握手过程更加高效。
* **更快的恢复机制**：QUIC 提供了更好的丢包恢复和重传机制，能够在网络丢包或延迟的情况下更快速地恢复连接。
* **连接迁移**：QUIC 支持连接迁移，允许在网络环境变化（如从 Wi-Fi 切换到移动数据）时保持连接不变。这提高了在不同网络条件下的连接稳定性。
* **优化的性能**：由于其设计可以减少延迟和提高数据传输效率，HTTP/3 在性能上相较于 HTTP/2 和 HTTP/1.1 有显著提升。

### HTTP/3.0 缺点
* `广泛支持度低`：HTTP/3.0 还在推广过程中，许多网站和服务尚未升级，可能导致不兼容的情况。
* `网络中间设备兼容性问题`：QUIC 的加密特性可能会让一些网络中间设备无法处理或过滤这些数据包，从而造成问题。
* `复杂性增加`：QUIC 协议引入了更多的加密和多路复用机制，这使得协议栈更加复杂，可能增加实现和维护的难度。
* `调试和监控困难`：QUIC 的加密层让网络流量分析变得更加困难，从而增加了调试和监控的挑战。
* `高延迟初始连接`：QUIC 的连接建立过程可能会在某些情况下造成额外的延迟，尤其是在网络环境不佳的情况下。
* `协议实现不一致`：不同实现的 QUIC 协议可能存在不兼容问题，这可能影响跨平台的协议一致性。
* `对旧设备支持差`：老旧设备和系统可能无法支持 QUIC 协议，从而无法享受 HTTP/3.0 的性能优势。
