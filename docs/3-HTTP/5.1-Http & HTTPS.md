# Http 和 HTTPS 应用层传输协议


超文本是一种以计算机为基础的文档管理技术，它将文本中的文字、图片、音频、视频等元素通过超链接的方式相互关联。用户可以通过点击超链接在不同的内容之间进行快速跳转和访问，从而打破了传统文本线性阅读的限制。


* HTTP（超文本传输协议）和 HTTPS（超文本传输安全协议）都是应用层协议。
* HTTP：它是互联网上应用最为广泛的一种网络协议，用于在 Web 浏览器和 Web 服务器之间传输超文本数据，如 HTML 页面、图片、视频等。它定义了客户端和服务器之间请求和响应的格式与规则。
* HTTPS：实际上是在 HTTP 的基础上，通过添加 SSL/TLS（安全套接层 / 传输层安全）协议来实现加密传输和身份验证等安全功能。HTTPS 在应用层和传输层之间增加了一个安全层，对数据进行加密处理，以确保数据的保密性、完整性和身份验证，其本质上仍然是基于 HTTP 协议来进行数据的请求和响应，因此也属于应用层协议。

  **协议方案**：HTTP 是超文本传输协议，信息是明文传输，**HTTPS 则是具有安全性的 SSL 加密传输协议**。
  **端口：**HTTP 的默认端口是 80，而 HTTPS 的默认端口是 443。
  **安全性：**HTTP 的信息传输是不安全的，信息可以被任何人捕获和查看。HTTPS 通过 SSL/TLS 协议对数据进行加密，保证了数据的完整性和私密性，防止数据在传输过程中被窃取或篡改。 因为它以**明文形式**发送数据，这意味着在网络上传输的所有信息都可以被中间人截获并阅读。这包括**敏感信息，如密码、信用卡号和其他个人信息，使得HTTP容易受到各种网络攻击**，如窃听、篡改和中间人攻击。
  **性能**：由于 HTTPS 需要进行加密和解密操作，所以在性能上会稍微低于 HTTP。但是随着技术的发展，这种差距已经非常小，几乎可以忽略不计。
  **SEO：搜索引擎优化（SEO）方面**，Google 等搜索引擎已经明确表示，HTTPS 网站在搜索排名中会得到一定的优先级。
  **证书：**HTTPS 需要到 **CA 申请证书，一般免费证书较少，因而需要一定费用**


## Https为什么更安全，在哪里用到了对称加密?

* HTTPS（HyperText Transfer Protocol Secure）是基于 HTTP 的一种安全版本，通过使用 TLS（传输层安全性）/SSL（安全套接层）协议来保护数据传输

* `加密`
  对称加密：在 HTTPS 连接中，对称加密用于加密数据传输。数据在客户端和服务器之间传输时会被加密，以防止第三方窃听或篡改。对称加密算法如 AES（高级加密标准）被用来加密实际传输的数据。
*  `身份验证`：
  * 公钥加密： HTTPS 使用公钥加密来验证服务器的身份。
  * 在建立连接时，`服务器会向客户端提供数字证书`，证书包含了服务器的公钥。
  * 客户端使用该公钥来`验证服务器的身份`，确保它连接的是合法的服务器而非伪装的假网站。
* `数据完整性`：
  * 消息认证码（MAC）：在数据传输过程中，HTTPS 使用`哈希函数和消息认证码（MAC）来确保数据的完整性`。
  * `任何数据的篡改都会导致认证失败`，从而可以检测到数据在传输过程中是否被篡改。


在 HTTPS 通信中，对称加密用于加密数据的传输。

* `握手阶段（非对称加密）：`
  * `公钥加密`：在 HTTPS 握手过程中，客户端和服务器通过公钥加密`进行身份验证和密钥交换`（非对称加密：用于身份验证和安全地交换对称密钥RSA）
    * 客户端会验证服务器的证书，并使用服务器的公钥加密一个随机生成的`对称密钥（会话密钥）`，然后发送给服务器。
  * `密钥交换`：服务器接收到加密的对称密钥后，使用自己的私钥解密，获得会话密钥。这个会话密钥是一个对称密钥，用于在客户端和服务器之间加密实际的数据传输。

* `数据传输阶段（对称加密）`
  * 一旦建立了安全连接，客户端和服务器使用这个对称密钥进行加密和解密实际传输的数据。对称加密算法（如 AES）被用来确保数据在传输过程中是加密的，从而保护数据的机密性。
  * 对称加密的优点是`计算效率高，适合大规模数据加密`


  非对称加密： 非对称加密使用一对密钥——公钥和私钥。公钥用于加密，私钥用于解密。公钥是公开的，任何人都可以获得，而私钥只有拥有者自己知道。
  对称加密：对称加密使用一个密钥进行加密和解密。对称加密算法如 AES 被用来加密实际传输的数据。
