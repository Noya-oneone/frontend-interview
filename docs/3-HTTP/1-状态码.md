# 状态码

## 1xx 信息性

* `100 Continue`：服务器已收到请求头，客户端应继续发送请求体（配合 `Expect: 100-continue`）。
* `101 Switching Protocols`：协议切换，如 HTTP 升级到 `WebSocket`。

## 2xx 成功

* `200 OK`：请求成功，正常返回。
* `201 Created`：资源创建成功（POST 新建后的标准响应）。
* `204 No Content`：处理成功但`无返回内容`（删除、更新操作常用；CORS 预检响应也常用）。
* `206 Partial Content`：`范围请求`成功，返回部分内容 —— 断点续传、视频拖动播放的基础（配合 `Range` / `Content-Range`）。

## 3xx 重定向

* `301 Moved Permanently`：`永久`重定向，新地址在 `Location` 头。浏览器与搜索引擎会`记住并更新索引`（对 SEO 重要），浏览器可能缓存该跳转。
* `302 Found`：`临时`重定向，如未登录跳转登录页。搜索引擎不更新索引。
* `304 Not Modified`：`协商缓存命中` —— 资源未变化，响应无 body，浏览器继续用本地缓存（见 [协商缓存 & 强缓存](./2-协商缓存%20&%20强缓存.md)）。
* 补充：`307 / 308` 是 302/301 的严格版，重定向时`不允许把 POST 改写成 GET`。

## 4xx 客户端错误

* `400 Bad Request`：请求`参数有问题`——缺参数、类型错误、格式非法。
* `401 Unauthorized`：`未认证` —— 没带凭证或凭证过期，先去登录。
* `403 Forbidden`：`已认证但无权限` —— 身份明确，就是不让访问（如内网 IP 限制）。
* `404 Not Found`：资源不存在。
* `405 Method Not Allowed`：路径存在但不支持该 HTTP 方法。
* `408 Request Timeout`：客户端`在规定时间内没发完请求`（弱网、丢包场景，见 [丢包](./丢包408.md)）。
* `429 Too Many Requests`：触发`限流`。

> **401 vs 403 是高频对比题**：401 = 你是谁我不知道（认证问题）；403 = 我知道你是谁但你不行（授权问题）。

## 5xx 服务器错误

* `500 Internal Server Error`：服务器内部异常（代码抛错未兜住）。
* `502 Bad Gateway`：网关/代理`从上游服务收到无效响应` —— 典型如 Nginx 后面的应用进程挂了。
* `503 Service Unavailable`：服务器`过载或维护中`，暂时无法处理。
* `504 Gateway Timeout`：网关`等待上游服务响应超时` —— 后端还活着但太慢。

> **502 vs 504**：502 是上游`响应不对`（连不上/挂了），504 是上游`响应太慢`（超时）。

## 常见考点

* **如何看待前端「接口报错」排查？** 4xx 先查自己（参数、token、跨域预检），5xx 找后端（502/504 先怀疑网关与上游服务状态）。
* **304 是错误吗？** 不是，它是缓存机制的正常一环，Network 面板里大量 304 说明协商缓存在工作。
* **重定向会丢失 POST 数据吗？** 301/302 历史上会被改写成 GET；要保持方法用 307/308。
