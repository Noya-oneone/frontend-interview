
# 协商缓存 & 强缓存

* 浏览器缓存资源存储在`本地缓存`中，包括内存缓存和磁盘缓存。
* **304(资源没有发生任何变化) - 继续使用本地缓存**

## 强缓存 （`静态资源、CDN 资源、版本化文件`）

* 如网站的 logo 图片、全局样式表），选择强缓存。通过设置较长的缓存过期时间（如一年），让浏览器在后续访问时直接从本地缓存读取，减少网络请求
 
* 强缓存**不需要向服务器发送请求**就可以直接使用缓存的资源。
* 强缓存主要通过 `Expires 和 Cache-Control`这两个 HTTP 响应头实现。
  * `Expires` 是 HTTP/1.0 的产物，表示资源的过期时间，
  * `Cache-Control` 是在 HTTP/1.1 中引入的，可以通过 `max-age` 等指令**控制资源**的缓存策略。
    ```js
    Cache-Control: max-age=3600 // 资源的缓存时间为 1 小时
    Expires: Wed, 21 Oct 2022 07:28:00 GMT // 资源的过期时间
    ```
* 强缓存的优点是减少了请求次数，提高了性能。
* 强缓存的劣势是可能会导致缓存过期，无法获取最新数据。 

## 协商缓存 （`动态内容、API 响应`）

* 经常更新的数据（如用户的实时订单信息），则使用弱缓存，每次请求时浏览器会先向服务器验证资源是否有更新，若未更新则使用本地缓存，保证数据的及时性

* 协商缓存需要向服务器发送请求，`由服务器决定是否使用缓存的资源`

  * Last-Modified 更适合于简单的缓存场景，但可能不够精确。- 表示资源最后修改的时间。
  * ETag 提供更高的灵活性和准确性，尤其在频繁变更的内容上更具优势。- 表示资源的唯一标识符，通常是资源内容的哈希值或版本号。

* **Last-Modified / If-Modified-Since**：
    * `服务器`通过 `Last-Modified` 响应头告诉客户端资源`最后一次修改的时间`。
    * `客户端`在下次请求时，会通过 `If-Modified-Since` 请求头告诉服务器资源在客户端`最后一次获取的时间`。
    * 如果服务器发现资源的最后修改时间晚于客户端提供的时间，就会返回新的资源，**否则返回 304**。

  ```js
    Last-Modified: Tue, 20 Jul 2024 08:00:00 GMT // 资源最后修改时间
    If-Modified-Since: Tue, 20 Jul 2024 08:00:00 GMT // 客户端上次获取资源的时间
  ```
* **ETag / If-None-Match**：
  * `服务器`通过 `ETag` 响应头给资源生成一个唯一的标识（可以理解为一个`版本号`）。
  * `客户端`在下次请求时，会通过 `If-None-Match` 请求头告诉服务器资源在`客户端的标识`。
  * 如果服务器发现资源的标识与客户端提供的不一致，就会返回新的资源， **否则返回304**。

    ```js
      ETag: "v1" // 是服务器生成的资源标识符，用于标识资源的版本
      If-None-Match: "v1" // 客户端上次获取资源的标识符
    ```

* 协商缓存的优点是确保缓存数据的有效性和一致性。
* 协商缓存的劣势是需要额外的网络请求来验证缓存。


### 缓存策略总结 

| 缓存策略  | 使用场景| Webpack 配置示例  |
|-|----|----|
| **强缓存**| 静态资源（CSS、JS、图片）、构建输出文件、不频繁变动的资源 | 使用 `[contenthash]` 生成唯一文件名 |
| **协商缓存**| 动态生成的资源、经常变动的内容、API 请求| 配置服务器端的 `Cache-Control` 和 `ETag` 头部 |

* nginx配置 （主要是配置html文件不强缓存，别的文件使用强缓存+协商缓存）
* 在输出的文件名中使用内容哈希（[contenthash]）可以确保当文件内容改变时，生成的新文件名也会随之改变，从而利用浏览器缓存，避免用户下载不必要的文件。
* 这意味着，如果文件没有变化，浏览器可以使用之前缓存的文件，而不需要重新请求，减少了网络带宽和加载时间。

 * **webpack持久化缓存**
* 在Webpack中，可以通过配置output.filename和output.chunkFilename来控制缓存。
如果你希望启用持久化缓存，可以在Webpack配置文件中使用output.filename来为输出的文件名添加contenthash，这样**只有当源文件内容变化时，才会生成新的输出文件**，从而利用浏览器缓存机制。

提供**长期缓存的插件**和loader，也应该确保配置正确，例如对于babel-loader，可以设置缓存目录：在babel-loader的配置中，**cacheDirectory选项使得Babel可以在磁盘上保存loader的缓存**，加快构建速度。

以下是一个简单的配置示例：

```javascript
module.exports = {
  entry: {
    main:"main.js",
    sub:"sub.js"
  },
  output: {
    path: "/dist",
    filename: "[name].[hash].js"
  }
  }
```








## 强缓存处理

### 利用 <link> 和 <script> 标签的 rel 和 href/src 属性
在 HTML 文件中引入 CSS 和 JavaScript 文件时，可以通过给 href 或 src 属性添加版本号参数，来控制强缓存的更新。当资源有更新时，修改版本号，浏览器会认为是新的资源，从而重新请求。

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Document</title>
    <!-- 通过添加版本号参数来控制缓存更新 -->
    <link rel="stylesheet" href="styles.css?v=2">
</head>
<body>
    <!-- 同样的方式处理 JavaScript 文件 -->
    <script src="script.js?v=2"></script>
</body>
</html>
```

###  使用 JavaScript 动态加载资源
* 在 JavaScript 中，可以使用 fetch API 或 XMLHttpRequest 动态加载资源，并通过修改请求的 URL 参数来绕过强缓存。
```js
// 使用 fetch API 动态加载资源并绕过缓存
const version = 2;
fetch(`data.json?v=${version}`)
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error fetching data:', error));
```

## 弱缓存处理

### 处理 ETag 和 Last-Modified 响应头
* 当使用 fetch API 或 XMLHttpRequest 发送请求时，可以手动处理服务器返回的 ETag 和 Last-Modified 响应头，并在下次请求时将其作为请求头发送给服务器。
```js
// 第一次请求资源
fetch('data.json')
  .then(response => {
    const etag = response.headers.get('ETag');
    const lastModified = response.headers.get('Last-Modified');
    // 存储 ETag 和 Last-Modified 信息
    localStorage.setItem('dataJsonETag', etag);
    localStorage.setItem('dataJsonLastModified', lastModified);
    return response.json();
  })
  .then(data => console.log(data))
  .catch(error => console.error('Error fetching data:', error));

// 下次请求时，携带 ETag 和 Last-Modified 信息
const storedETag = localStorage.getItem('dataJsonETag');
const storedLastModified = localStorage.getItem('dataJsonLastModified');
const headers = {};
if (storedETag) {
  headers['If-None-Match'] = storedETag;
}
if (storedLastModified) {
  headers['If-Modified-Since'] = storedLastModified;
}

fetch('data.json', { headers })
  .then(response => {
    if (response.status === 304) {
      // 资源未更新，使用本地缓存
      console.log('Resource not modified, using cached data');
    } else {
      return response.json();
    }
  })
  .then(data => {
    if (data) {
      console.log(data);
    }
  })
  .catch(error => console.error('Error fetching data:', error));
```

### 2. 手动控制缓存更新
在某些情况下，可以通过 JavaScript 手动清除缓存或强制更新资源。例如，在用户进行特定操作（如点击刷新按钮）时，清除缓存并重新加载资源。
```js
// 清除缓存并重新加载页面
function clearCacheAndReload() {
  if ('caches' in window) {
    caches.keys().then(cacheNames => {
      cacheNames.forEach(cacheName => {
        caches.delete(cacheName);
      });
    });
  }
  // 重新加载页面
  location.reload(true);
}

// 绑定刷新按钮事件
const refreshButton = document.getElementById('refresh-button');
refreshButton.addEventListener('click', clearCacheAndReload);
```

## 处理 Service Worker 缓存
* Service Worker 可以在浏览器和网络之间充当代理，拦截请求并处理缓存。可以通过 Service Worker 来实现更灵活的缓存策略，包括强缓存和弱缓存。

```js
// service-worker.js
self.addEventListener('install', event => {
  event.waitUntil(
    caches.open('my-cache-v1')
      .then(cache => cache.addAll([
        '/',
        '/styles.css',
        '/script.js'
      ]))
  );
});

self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request)
      .then(response => {
        if (response) {
          // 如果缓存中有匹配的资源，直接返回
          return response;
        }
        // 否则，从网络请求资源
        return fetch(event.request);
      })
  );
});
// 在主页面中注册 Service Worker：
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/service - worker.js')
      .then(registration => {
        console.log('Service Worker registered successfully:', registration);
      })
      .catch(error => {
        console.error('Service Worker registration failed:', error);
      });
  });
}
```
