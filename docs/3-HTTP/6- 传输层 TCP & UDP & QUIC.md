
# 传输层 TCP 与 UDP 区别
TCP（传输控制协议）与UDP（用户数据报协议）是计算机网络中两种重要的传输层协议，它们在多个方面存在显著的区别。以下是TCP与UDP的主要区别：

| 特性 | TCP| UDP|
|------------------|--------------------------------------|------------------------------------|
| **协议类型**| 面向连接的协议| 无连接的协议|
| **可靠性**| 可靠（提供数据传输确认和重传机制）| 不可靠（不提供数据传输确认和重传机制）|
| **数据顺序**| 保证数据顺序 | 不保证数据顺序|
| **流量控制**| 支持流量控制 | 不支持流量控制|
| **拥塞控制**| 支持拥塞控制 | 不支持拥塞控制|
| **延迟**| 延迟较高（因需建立连接和确认）| 延迟较低|
| **数据包大小**| 数据包大小有限（通常 64 KB 以下）| 数据包大小更灵活|
| **头部开销**| 较高（头部较大，至少 20 字节） | 较低（头部较小，8 字节）|
| **连接建立**| 需要三次握手建立连接| 不需要连接建立|
| **应用场景**| 适用于需要可靠传输的应用，如网页浏览、电子邮件等 | 适用于对延迟敏感或要求较少的应用，如视频流、在线游戏等 |


## TCP 与 UDP 的区别

1. **连接性**
 - **TCP**：是一种`面向连接`的协议。在数据传输之前，TCP要求发送方和接收方`先建立连接`，即进行`三次握手过程`，以确保双方都已准备好接收数据。数据传输完成后，还需要进行四次挥手来释放连接。
 - **UDP**：是一种`无连接`的协议。发送方在发送数据之前不需要与接收方建立连接，`直接发送数据`报即可。这使得UDP在实时性要求较高的应用中具有优势。

2. **可靠性**
 - **TCP**：对数据的可靠性要求`非常严格`。它使用确认和重传机制来确保数据的完整性和正确性。如果接收方没有收到数据或数据有误，发送方会重新发送数据，直到接收方确认收到正确的数据为止。
 - **UDP**：对数据的可靠性要求较低。它不提供确认、重传和流量控制机制。`如果发送的数据丢失或损坏，UDP不会进行重传`，而是直接让接收方收到的数据可能不完整或错误。

3. **速度和效率**
 - **TCP**：由于需要建立连接和使用`确认重传机制`，TCP的传输速度相对较慢。特别是在网络拥堵时，TCP的拥塞控制机制会进一步`降低传输速度`。
 - **UDP**：不受拥塞控制的限制，且没有连接建立和确认重传的开销，因此UDP的传输速度通常比TCP更快。这使得UDP在实时性要求较高的应用中更为适用。

4. **数据包大小**
 - **TCP**：将数据划`分为较小的数据包（TCP段）进行传输`，并根据网络状况进行调整。它没有固定的数据报大小限制。
 - **UDP**：允许发送方一次性`将多个数据包打包成一个较大的数据报（UDP数据报）进行传输`。数据报的大小通常在应用层自行决定。

5. **适用场景**
 - **TCP**：适用于对数据可靠性要求较高的应用场景，如`文件传输、电子邮件、网页浏览`等。这些应用需要确保数据的完整性和正确性，即使传输速度稍慢也在所不惜。
 - **UDP**：适用于对数据实时性要求较高的应用场景，如`音频和视频流传输、网络游戏、实时通信`等。这些应用对数据的实时性要求较高，但对数据的完整性要求相对较低。



| 特性| UDP | QUIC |
|-|-|-|
| **协议类型**| 基础传输层协议 | 传输层协议，基于 UDP 实现|
| **连接建立**| 无连接建立 | 集成连接建立过程，减少延迟|
| **可靠性**| 不可靠 | 提供可靠性（包括重传机制和数据确认）|
| **流量控制**| 不支持流量控制 | 支持流量控制 |
| **拥塞控制**| 不支持拥塞控制 | 支持拥塞控制 |
| **加密**| 无内建加密 | 内建加密（集成 TLS） |
| **头部压缩**| 无头部压缩 | 支持头部压缩（QPACK）|
| **多路复用**| 不支持 | 支持多路复用 |
| **数据顺序**| 不保证数据顺序 | 支持数据顺序控制（在流级别） |
| **网络迁移**| 不支持 | 支持连接迁移（网络环境变化时保持连接） |
| **应用场景**| 适用于对延迟敏感但不需要可靠性的应用，如实时通信、视频流 | 适用于需要高效、可靠和安全的网络传输，如网页浏览、流媒体 |
