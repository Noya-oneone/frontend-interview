# 签名过程

## 1. 准备待签名的字符串

待签名的字符串由三个部分组成：

1. HTTP请求方法（GET、POST、PUT、DELETE等）
2. 请求URI（请求的资源路径）
3. 请求头（请求头中包含的内容，如Content-Type、Date等）


## 2. 计算签名

将待签名的字符串进行URL编码，然后按照如下步骤计算签名：

1. 将请求方法、请求URI、请求头中的Content-Type、Date等信息按顺序拼接成字符串。
2. 将拼接好的字符串进行MD5加密，得到签名值。
3. 将签名值进行URL编码，得到最终的签名字符串。

生成Hash值的方法可以使用MD5、SHA-256等算法。



## 3. 加入请求头

将最终的签名字符串加入到请求头中，请求头中应包含Authorization字段，其值应为：

```
Authorization: Signature keyId="your-key-id",algorithm="hmac-sha256",headers="date (request-target) content-type",signature="your-signature"
```

其中：

- keyId：密钥ID，用于标识用户的密钥。
- algorithm：签名算法，目前支持HMAC-SHA256。
- headers：请求头中包含的字段，用空格分隔。
- signature：签名值，经过URL编码。

## 4. 发送请求

将请求头加入到HTTP请求中，发送请求。

## 5. 验证签名

服务端收到请求后，会验证请求头中的Authorization字段，并按照如下步骤验证签名：

1. 解析Authorization字段，获取keyId、algorithm、headers、signature等信息。
2. 从数据库中获取keyId对应的密钥。
3. 按照算法计算签名值。
4. 验证签名值是否与请求头中的signature相同。

如果验证通过，则认为请求是合法的，可以继续处理请求。
