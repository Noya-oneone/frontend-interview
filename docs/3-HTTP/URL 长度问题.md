# URL 长度问题

`HTTP 协议本身不限制 URL 长度`，限制来自浏览器与服务器的实现：

| 环节 | 限制 | 说明 |
|--|--|--|
| **IE（历史）** | 2083 字符 | 「2000 字符」经验值的来源 |
| **Chrome** | 约 2MB（地址栏实际可用远小于此） | 超长 URL 渲染与分享都会出问题 |
| **Firefox / Safari** | 数万字符级 | 实现各异 |
| **Apache** | 默认 8190 字节 | `LimitRequestLine` 可调 |
| **Nginx** | 默认约 4K~8K | `large_client_header_buffers` 可调，超限返回 `414 URI Too Long` |
| **CDN / 网关 / 日志系统** | 各有上限 | 全链路中`最短的一环`决定实际可用长度 |

## 实践建议

* 兼容性经验值：**URL 控制在 2000 字符以内**。
* 需要传大量数据时改用 `POST` 请求体（见 [GET & POST](./7.1-Get%20&%20Post.md)）；分享类长参数考虑`短链服务`或把状态存服务端换取 ID。
* 超限的典型症状：Nginx 返回 `414`，或请求在某层网关被静默截断导致参数丢失。

## 常见考点

* **为什么 GET 参数长度有限而 POST 没有？** 并非协议规定，而是 URL 要经过地址栏、日志、代理等所有环节，任何一环都可能设限；body 只受服务器 `client_max_body_size` 类配置约束。
