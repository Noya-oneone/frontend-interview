# 浏览器的垃圾回收机制

* Garbage Collection, GC）是用于`管理内存`的一个重要功能
* 它`会自动检测并释放不再使用的内存，防止内存泄漏，确保应用程序高效运行`。
    * 无引用：对象不再被引用。
    * 循环引用：对象之间互相引用，但不再被外界访问。
    * 内存泄漏：由于错误引用导致的未被回收的内存。
    * 过期数据：数据已被替代或过时，不再有实际用途。


## 垃圾回收机制

* 浏览器的垃圾回收机制主要基于`标记-清除算法`（Mark-and-Sweep Algorithm）和`引用计数（Reference Counting）算法`。

### 标记-清除算法-最常用的垃圾回收算法

* `标记阶段`：垃圾回收器从`根对象`（通常是全局对象和局部变量）开始，`递归地遍历所有可达对象`，并进行标记。
* `清除阶段`：未被标记的对象被认为是不可达的（即不再使用），将会被清除并释放内存。
* 它将内存分为三部分：`已使用`、`未使用`、`垃圾`。
* 程序运行时，会将内存中所有存活的对象标记为`已使用`，然后清除`未使用`的对象，最后再清除`垃圾`。

* 缺点：标记-清除算法的缺点是效率低下，因为它`需要移动大量的对象，导致程序暂停`。
* 优点：能有效处理循环引用的问题，不会出现内存泄漏

### 引用计数算法

* 引用计数算法是另一种垃圾回收算法。
* 它跟踪每个对象的引用数量，当一个对象的`引用数量为0时`，说明该对象不再被使用，可以进行回收。
* 无法处理`循环引用`的问题，如果两个对象`互相引用`，引用计数永远不会变为零，导致`内存泄漏`。


## 增量垃圾回收（Incremental GC）：

* 将垃圾回收过程拆分为多个小步骤，逐步完成，减少每次垃圾回收的停顿时间，提升应用程序的响应性。

## 分代垃圾回收（Generational GC）：

* 将内存分为几代（`如新生代和老年代`），`新生代中的对象生命周期较短，老年代中的对象生命周期较长`。
* 新生代的垃圾回收更频繁且快速，老年代的垃圾回收较少，但更彻底。
* 通过这种方式，可以提高垃圾回收的效率和性能。

## 并发垃圾回收（Concurrent GC）：

* `垃圾回收和应用程序执行同时进行`，在后台完成垃圾回收工作，进一步减少应用程序的停顿时间。

V8 垃圾回收机制：使用`标记-清除和分代收集算法`，分为新生代和老生代进行优化。
JavaScript 垃圾回收：基于 V8 的垃圾回收机制，使用`引用计数、标记-清除、标记-整理和分代回收`等技术来管理内存。
