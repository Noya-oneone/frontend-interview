# 关系型数据库 VS 非关系型数据库

## 核心对比

| 维度 | 关系型（RDBMS） | 非关系型（NoSQL） |
|--|--|--|
| 代表 | MySQL、PostgreSQL、Oracle | MongoDB（文档）、Redis（键值）、Cassandra（列族）、Neo4j（图） |
| 数据模型 | `表格`：行是记录、列是字段，schema 固定 | 文档 / 键值 / 列族 / 图，`schema 灵活` |
| 查询 | SQL，支持复杂 `JOIN` 与聚合 | 各自的 API / 查询语言，通常按键或索引查 |
| 事务 | `ACID` 完整支持，强一致性 | 传统上弱（最终一致性 BASE）；但并非不支持 —— MongoDB 4.0+ 有多文档事务、Redis 有 MULTI/Lua 原子性 |
| 扩展 | 擅长`垂直扩展`（加配置）；分库分表做水平扩展`复杂` | 天生面向`水平扩展`（分片、加节点） |
| 适用 | 强一致业务：订单、支付、账务 | 高并发读写、海量数据、结构多变：缓存、日志、社交 feeds |

> 记忆锚点：**关系型强在一致性与复杂查询，NoSQL 强在横向扩展与灵活 schema** —— 别记反。

## Redis 的典型使用场景

* `缓存`：热点数据快速读写，挡在数据库前面降低负载。
* `会话管理`：集中存储 session，支撑多实例部署。
* `排行榜 / 计数`：Sorted Set 天然适合实时排名。
* `消息队列`：List / Stream 做任务队列与异步解耦。
* `分布式锁`：SET NX + 过期时间。

## 常见考点

* **什么时候选 NoSQL？** 数据结构频繁演化、读写量级要求水平扩容、可接受最终一致性；反之涉及资金与强一致约束选关系型。实际架构常是`两者搭配`（MySQL 存主数据 + Redis 缓存）。
* **MongoDB 和 MySQL 的直观区别？** 文档（JSON 结构，嵌套即关联）vs 表（范式化，JOIN 关联）；前端全栈项目起步快常用 MongoDB，事务性业务用 MySQL。
