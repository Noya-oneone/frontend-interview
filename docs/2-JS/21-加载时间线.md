# 页面加载时间线

从输入 URL 到页面可交互，浏览器渲染侧的关键阶段：

1. **解析 HTML，构建 DOM 树**：自上而下解析；遇到`同步 <script>` 暂停解析，先下载并执行完再继续。
2. **下载并解析 CSS，构建 CSSOM**：CSS 不阻塞 DOM 解析，但`阻塞渲染`，也阻塞后续同步脚本执行（脚本可能读样式）。
3. **执行 JavaScript**：
   * `同步脚本`：下载完立即执行，`阻塞 HTML 解析`。
   * `defer`：并行下载，DOM 解析完、`DOMContentLoaded 前`按顺序执行。
   * `async`：并行下载，`下载完立即执行`，顺序不保证（详见 [script](../0-HTML/<script>.md)）。
4. **`DOMContentLoaded` 触发**：DOM 树就绪（defer 脚本已执行完）。
5. **渲染树 → 布局 → 绘制**：DOM + CSSOM 合成渲染树，计算几何（Layout），栅格化绘制（Paint），合成上屏（Composite）—— 首次绘制即 FP/FCP。
6. **`load` 触发**：图片、样式、iframe 等全部资源加载完毕（见 [onload & DOMContentLoaded](./20-onload%20&%20DOMContentLoaded%20.md)）。

后续 JS 修改 DOM 或样式，会按影响范围触发`重排（reflow）→ 重绘（repaint）→ 合成`的部分流程。

## 常见考点

* **为什么 CSS 放头部、JS 放底部（或加 defer）？** CSS 越早到达越早完成 CSSOM、避免渲染阻塞拉长；同步 JS 放头部会卡住解析造成白屏。
* **DOMContentLoaded 会等 CSS 吗？** DOM 解析本身不等 CSS；但若 CSS 之后还有同步脚本，脚本等 CSSOM、解析等脚本，`间接`推迟 DOMContentLoaded。
* **量化指标**：FP/FCP（首次绘制/内容绘制）、LCP（最大内容绘制）、TTI（可交互时间）分别对应此时间线的不同节点。
