## **进程和线程**

* `线程`是进程内部的`执行单元`，它们`共享相同的资源`，
* 而`进程`则是`操作系统`进行资源分配和调度的`基本单位`。
    * `内存和资源分配`：操作系统根据系统资源（如内存、CPU）和进程的需求动态分配内存。
    每个进程拥有独立的内存空间和资源。
    * `进程创建开销`：创建和管理多个进程会增加系统开销，如内存和上下文切换的消耗。

| 项目   | **进程**                          | **线程**                        |
|--------|-------------------------------|-----------------------------|
| `定义`   | 操作系统中`资源分配`的最小单位  | 操作系统中`任务调度`的最小单位|
| `内存 `  | `独立`的内存空间                | `共享`进程的内存空间          |
| `创建`   | 开销较大，速度较慢            | 开销较小，速度较快          |
| `通信`   | 需要使用进程间**通信机制**        | 线程间**直接通信**             |
| `崩溃`   | 一个进程崩溃不会影响其他进程  | 线程崩溃可能导致进程崩溃    |
| `资源消耗` | 资源消耗大，稳定性好          | 资源消耗小，稳定性差        |

* `餐厅（进程）`是一个独立的商业实体，有自己的厨房、菜单和员工。这就像进程拥有自己的独立内存空间和系统资源。
* `厨师（线程）` 在餐厅（进程）里工作，他们共享厨房资源，比如炉子和食材。
* `创建和关闭成本`：开一家新餐厅（创建进程）的成本比雇佣一个新厨师（创建线程）要高，因为餐厅需要更多的设施和准备工作。
雇佣或解雇厨师比开设或关闭餐厅要简单快捷。
* `通信`：如果两家餐厅需要交换信息，比如食谱或供应商信息，他们可能需要通过**电话或电子邮件**（进程间通信）。
而厨师之间可以直接交谈，因为他们都在同一个厨房里（线程间通信）。
* `地址空间`：每个餐厅都有自己的厨房和存储空间，是相互隔离的。
厨师们则共享同一个厨房和存储空间。
* `稳定性`：如果一家餐厅出现问题，比如厨房发生火灾，通常不会影响到其他餐厅。但如果一个厨师出现问题，比如严重受伤，可能会影响到整个餐厅的运作。


## 死锁

* `死锁（Deadlock`）是指两个或多个进程在执行过程中，因为互`相等待对方释放资源`而陷入`永远无法继续执行`的状态。简单来说，就是一组进程中，每个进程都在等待其他进程所持有的资源，导致这些进程都无法继续执行。
* 形成死锁的四个必要条件
    * `互斥条件`：一个资源每次只能被一个进程使用。
    * `请求和保持条件`：一个进程因请求资源而阻塞时，对已获得的资源保持不放。
    * `不剥夺条件`：进程已获得的资源，在未使用完之前，不能被剥夺。
    * `循环等待条件`：若干进程之间形成一种头尾相接的循环等待资源关系。

### 解决死锁的方法

* 预防死锁：
    * 破坏互斥条件：当资源被独占时，其他进程必须等待。
    * 破坏请求和保持条件：进程申请资源时，一次性申请足够的资源。
    * 破坏不剥夺条件：进程获得资源后，不能强行剥夺，只能在使用完后释放。
    * 破坏循环等待条件：保证资源分配合理，避免资源的长时间等待。
    * 使用`Promise和Async/Await`进行`异步编程`，可以`避免直接操作锁`，从而减少死锁的可能性
    * 在等待资源时`设置超时`，可以避免进程无限期等待
    * 为资源分配一个`全局的唯一顺序编号`，并按顺序申请资源
    * 现成的并发库-`async-mutex、semaphore-async-await`等可以帮助我们避免死锁
* 避免死锁：
    * `资源有限分配`：确保每个进程都能获得足够的资源。
    * `资源动态分配`：进程运行过程中动态分配资源，避免长时间等待。
    * `银行家算法`：一种动态分配资源的方法，可以检测并解除死锁。
* 检测和恢复死锁：
    死锁检测：通过维护资源分配图或使用检测算法（例如银行家算法的简化版），`定期检测系统`是否处于死锁状态。
        * `资源分配图`：对于小型应用，可以使用资源分配图来动态检测死锁。例如，在操作系统中，内核会定期扫描进程和资源的状态，判断是否存在死锁。
    进程终止：终止一个或多个死锁进程，直到解除死锁。可以采用代价`最低的进程（如计算时间或持有资源最少）优先终止`。
    资源剥夺：`强制撤销`某些进程所持有的资源，并重新分配给其他进程。这可能需要保存和恢复进程状态，复杂度较高。

## 并发

* 并发（Concurrency）是指两个或多个事件在同一时间间隔发生。
* 并行（Parallelism）是指两个或多个事件在同一时间间隔发生，但互不影响。

### 并发实际场景
    * 数据获取：批量获取数据。
    * 文件上传/下载：多个文件同时上传/下载。
    * 用户交互：处理多个用户事件。

### JS 实现多进程、多线程
* JS 单线程： 实际处理并发主要依赖于异步编程模型
* Node.js 的子进程：Node.js 提供了 `child_process 模块`，允许创建子进程执行 JavaScript 代码。
    子进程之间的通信通过 IPC（进程间通信）进行。
    * `send() 和 on('message')`：
        * 父进程可以通过 send() 方法发送消息给子进程。
        * 子进程可以通过 process.on('message') 监听消息。
    * `stdin 和 stdout`：可以通过标准输入和输出流传递数据。
    * `fork() 方法`：可以创建子进程，并在父进程和子进程之间共享内存。
* Node.js 的 `Cluster 模块`：Cluster 模块可以创建多个子进程，并且可以共享端口。
    * 父进程负责管理子进程，当子进程发生异常退出时，可以自动重启。
    `Web 服务进程`：处理用户请求、展示商品信息。
    `订单处理进程`：处理用户订单、库存管理。
    `支付处理进程`：处理支付事务、发票生成。
    `数据分析进程`：进行数据分析和报告生成。

* `资源消耗`：每个 Web Worker 占用系统资源，如内存和 CPU 时间。创建过多的 Web Worker 可能导致内存消耗增加和 CPU 资源争用，降低整体性能。
* `线程切换开销`：多个 Web Worker 会增加线程切换的开销。频繁的上下文切换可能会导致性能下降，特别是在处理大量并发任务时。
* `复杂性增加`：管理和协调大量的 Web Worker 会增加程序的复杂性。需要处理多个 Worker 之间的通信和同步，可能导致代码更复杂且更难以调试。 
* `调度开销`：操作系统和浏览器的线程调度机制可能会受到影响。过多的线程可能导致调度开销增加，影响整体应用的响应时间。
* `任务分配和负载均衡`：创建大量 Web Worker 并不一定能提高性能。需要合理地将任务分配给 Web Worker，以确保负载均衡和高效的资源使用。




## 浏览器中有哪些进程和线程
| 类型         | 描述                                      | 示例                              |
|--------------|-------------------------------------------|-----------------------------------|
| **浏览器进程**  | 管理浏览器的界面、标签页、窗口等。          | 处理用户界面、菜单、书签等。       |
| **渲染进程**    | 处理网页的渲染，包括 HTML、CSS 和 JavaScript。| 每个标签页或窗口通常有一个渲染进程。|
| **GPU 进程**    | 处理图形渲染和加速，提升性能。              | 渲染动画、视频、WebGL 内容等。      |
| **网络进程**    | 处理网络请求和数据传输。                   | 处理 HTTP 请求、WebSocket 连接等。|
| **插件进程**    | 管理和运行浏览器插件或扩展。                | 处理扩展的功能和用户交互。         |
| **崩溃报告进程**| 处理浏览器崩溃和生成崩溃报告。              | 收集崩溃信息并发送给开发者。       |

| 线程类型        | 描述                                      | 示例                              |
|-----------------|-------------------------------------------|-----------------------------------|
| **主线程**      | 处理 UI 更新、事件处理和 JavaScript 执行。  | 执行 JavaScript 代码、处理 DOM 操作。|
| **渲染线程**    | 渲染 HTML 和 CSS，执行 JavaScript。         | 渲染页面内容、布局计算等。         |
| **Web Worker 线程** | 在后台线程中执行 JavaScript，避免阻塞主线程。 | 处理数据、执行计算密集型任务。     |
| **定时器线程**  | 处理定时器（如 `setTimeout` 和 `setInterval`）。| 执行定时器回调函数。              |
