# 进程和线程

## 概念

* `进程`是操作系统`资源分配`的基本单位，拥有独立的内存空间。
* `线程`是进程内部的`执行单元`，同进程的线程`共享内存与资源`。

| 项目 | **进程** | **线程** |
|--|--|--|
| `定义` | 资源分配的最小单位 | 任务调度的最小单位 |
| `内存` | 独立的内存空间 | 共享进程的内存空间 |
| `创建` | 开销较大，速度较慢 | 开销较小，速度较快 |
| `通信` | 需要进程间通信机制（IPC） | 可直接读写共享内存 |
| `崩溃` | 一个进程崩溃不影响其他进程 | 线程崩溃可能拖垮整个进程 |

餐厅类比：`餐厅（进程）`是独立商业实体，有自己的厨房和员工；`厨师（线程）`在餐厅内共享厨房资源。开新餐厅（建进程）比雇厨师（建线程）贵；餐厅之间要靠电话联系（IPC），厨师之间直接交谈（共享内存）；一家餐厅失火不影响别家，一个厨师出事可能影响整家店。

## 并发与并行

* `并发（Concurrency）`：一段时间内`交替处理`多个任务（单核也能并发）。
* `并行（Parallelism）`：`同一时刻真正同时执行`多个任务（需要多核/多处理器）。
* JS 单线程靠`异步 + 事件循环`实现并发；要用满多核，浏览器靠 Web Worker，Node 靠子进程 / worker_threads / cluster。

## JS 实现多进程、多线程

* **Node `child_process`**：创建子进程执行任务。
  * `fork()` 专用于派生 Node 脚本，自动建立 `IPC 通道`（不是共享内存）：父进程 `child.send()` 发消息、子进程 `process.on('message')` 接收；也可通过 stdin/stdout 传数据。
  * `spawn / exec` 运行任意命令。
* **Node `cluster` 模块**：按 CPU 核数 fork 多个 worker `共享同一端口`，主进程负责分发连接与故障重启 —— Node 服务多核部署的经典方案。
* **Node `worker_threads`**：真正的多`线程`，可通过 `SharedArrayBuffer` 共享内存，适合 CPU 密集计算。
* **浏览器 Web Worker**：多线程计算，`postMessage / onmessage` 通信（详见 [Web Worker](../0-HTML/*%20Web%20Worker.md)）。
  * 不宜滥用：每个 Worker 占内存与 CPU，过多 Worker 带来线程切换与通信协调开销，需按任务量做负载均衡。

## 死锁

* `死锁`：多个进程（线程）`互相等待对方释放资源`，全部永远阻塞。
* 四个必要条件（同时满足才会死锁）：`互斥`、`请求和保持`、`不剥夺`、`循环等待`。
* 应对思路：
  * `预防`：破坏四条件之一 —— 一次性申请全部资源（破坏请求保持）、按`全局统一顺序`申请资源（破坏循环等待）、等待加`超时`。
  * `避免`：银行家算法等动态分配策略。
  * `检测与恢复`：维护资源分配图定期检测；发现后按代价最低原则`终止进程`或`剥夺资源`。
* JS 层面：单线程本身不会锁死资源，但 async 代码互相 await 对方的锁同样会「逻辑死锁」；用 `async-mutex` 等库并保持加锁顺序一致。

## 浏览器中的进程与线程（Chrome 多进程架构）

| 进程 | 职责 |
|--|--|
| **浏览器主进程** | 界面、标签管理、下载、权限协调 |
| **渲染进程** | 每个站点隔离一个：解析 HTML/CSS、执行 JS、排版绘制 |
| **GPU 进程** | 图形合成与硬件加速 |
| **网络进程** | HTTP 请求、WebSocket、缓存 |
| **插件/扩展进程** | 隔离运行扩展 |

渲染进程内部的主要线程：

| 线程 | 职责 |
|--|--|
| **主线程** | 执行 JS、样式计算、布局、绘制指令生成 —— JS 与渲染互斥的根源 |
| **合成线程** | 图层合成、滚动响应，不被主线程阻塞（见 [GPU 加速](../1-CSS/*%20GPU加速.md)） |
| **Worker 线程** | Web Worker / Service Worker 的执行环境 |
| **定时器/网络等内部线程** | 计时到期、IO 完成后把回调投递回主线程的事件循环 |

## 常见考点

* **为什么每个标签页崩溃互不影响？** 多进程架构，渲染进程相互隔离。
* **Node 如何利用多核？** `cluster`（多进程分摊连接）或 `worker_threads`（线程池算力），按 IO 密集 / CPU 密集选择。
* **fork 出的子进程共享内存吗？** 不共享，靠 IPC 消息传递；需要共享内存用 `worker_threads` + `SharedArrayBuffer`。
