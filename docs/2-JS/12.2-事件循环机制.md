# 事件循环机制

## 事件循环（Event Loop）
* 事件循环（Event Loop）是处理`异步编程`的关键概念，尤其是在单线程环境下（如 JavaScript）`保证非阻塞操作的能力`
* 一个事件循环从执行一个宏任务开始，到所有微任务执行完毕，并且页面渲染（如果有的话）完成为止。这个过程即为一个完整的事件循环。
* 每个事件循环都是独立的

* 在JavaScript中，setTimeout、Promise 和 async/await 的执行顺序由事件循环（Event Loop）决定
* `同步任务`：在主线程上`按顺序执行`。  
    * 首先执行所有同步任务，从上到下按顺序执行
    * 遇到`异步任务`，如`setTimeout`或`Promise`，将其添加到`事件队列`中，等待主线程空闲时执行。
    * 主线程执行完所有同步任务后，开始执行`事件队列`中的异步任务，即`setTimeout`或`Promise`的回调函数。
    * 遇到`微任务`，如`Promise`的回调函数，将其添加到`微任务队列`中，等待当前`事件循环`的结束。
* `微任务（Microtasks）`：包括 `Promise 的回调`和 `async/await` 中 await 之后的代码，它们会在`当前事件循环`的结束前执行。
    * 微任务是较小的任务单元，用于在当前宏任务完成后立即执行。微任务通常用来处理需要在同一个事件循环中完成的短小任务。
    * Promise.then
    * MutationObserver（浏览器环境）
    * process.nextTick（Node.js 环境）
* `宏任务（Tasks）`：包括 setTimeout 的回调，它们会在`微任务执行完毕后执行`。
    * 宏任务是较大的任务单元，常用于一些异步操作的回调。
    * 每次事件循环的开始都会先执行一个宏任务，宏任务执行完毕后，再执行所有的微任务，然后才开始下一次事件循环。
    * setTimeout
    * setInterval
    * setImmediate（Node.js 环境）
    * I/O 操作（如文件读取，网络请求等）
    * UI 渲染（浏览器环境）

    <!-- 1、首先执行所有同步代码（这也是一个宏任务）。 -->
    <!-- 2、在当前宏任务执行完毕后，执行所有微任务。 -->
    <!-- 3、当所有微任务执行完毕后，开始下一个宏任务。 -->

```javascript

console.log('同步任务开始'); // 1

setTimeout(() => {
  console.log('setTimeout'); // 6
}, 0);

Promise.resolve().then(() => {
  console.log('Promise 回调'); // 4
});

(async () => {
  console.log('async 函数开始'); // 2
  await null; // 将 await 放入微任务队列 
  console.log('async 函数中的 await 后的代码'); // 5
})();

console.log('同步任务结束'); // 3

```
