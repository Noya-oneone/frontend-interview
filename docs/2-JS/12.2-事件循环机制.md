# 事件循环机制

## 事件循环（Event Loop）

* JavaScript 是`单线程`的，事件循环是它在单线程下实现`非阻塞异步`的核心机制。
* 一轮循环：取出`一个宏任务`执行 → `清空整个微任务队列` →（浏览器视情况执行渲染）→ 取下一个宏任务。

执行顺序规则：

1. 先执行`同步代码`（整段 script 本身就是第一个宏任务），从上到下。
2. 遇到异步 API 时注册回调：宏任务回调进`宏任务队列`，微任务回调进`微任务队列`。
3. 当前宏任务执行完，`把微任务队列一次性清空`（执行中新产生的微任务也在本轮继续清，直到队列为空）。
4. 然后才取下一个宏任务，如此往复。

## 微任务 vs 宏任务

| | 微任务（Microtask） | 宏任务（Macrotask / Task） |
|--|--|--|
| 时机 | `当前宏任务结束后立即`、下一个宏任务之前 | 每轮循环取`一个`执行 |
| 来源 | `Promise.then/catch/finally`、`await` 之后的代码、`queueMicrotask`、`MutationObserver`、`process.nextTick`（Node，优先级最高） | `setTimeout / setInterval`、`setImmediate`（Node）、I/O 回调、UI 事件回调、`MessageChannel` |
| 特点 | 一轮内`全部清空`，可能「饿死」渲染（微任务无限自我调度会卡死页面） | 之间穿插微任务清空与渲染机会 |

> 渲染（样式计算、布局、绘制）发生在微任务清空之后、下一个宏任务之前，由浏览器按帧节奏决定是否执行 —— 所以「微任务先于渲染，宏任务后于渲染」是常考结论。

## 示例

```javascript
console.log('同步任务开始'); // 1

setTimeout(() => {
  console.log('setTimeout'); // 6（宏任务）
}, 0);

Promise.resolve().then(() => {
  console.log('Promise 回调'); // 4（微任务，先入队）
});

(async () => {
  console.log('async 函数开始'); // 2（async 函数体在 await 前是同步的）
  await null;                    // await 之后的代码进入微任务队列
  console.log('await 后的代码'); // 5
})();

console.log('同步任务结束'); // 3
```

## 常见考点

* **为什么 `setTimeout(fn, 0)` 也不是立即执行？** 回调要等`本轮同步代码 + 全部微任务`执行完才轮到；且规范对嵌套定时器有最小 4ms 钳制。
* **`await` 后面的代码相当于什么？** `Promise.resolve(表达式).then(后续代码)`，即微任务（例题见 [事件循环手写题](./1.md)）。
* **Node 与浏览器事件循环的差异？** Node 的宏任务分多个阶段（timers → poll → check 等），`setImmediate` 在 check 阶段；`process.nextTick` 在每个阶段切换前清空、优先于 Promise 微任务。
