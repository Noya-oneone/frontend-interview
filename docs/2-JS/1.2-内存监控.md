# 内存监控

## 内存泄漏

内存泄漏指的是程序运行过程中，由于某些原因导致程序占用的内存越来越多，最终导致系统内存不足，系统崩溃，甚至导致程序崩溃。

## 内存监控

内存监控是指通过某种手段实时监控程序的内存使用情况，包括程序占用的内存大小、内存分配情况、内存泄漏情况等。

### Performance Panel 内存监控
* `JS Heap（JavaScript 堆内存）`
    * 含义：这是 JavaScript 代码所使用的内存空间，存储了对象、函数以及其他动态分配的内存。堆内存的大小随着 JavaScript 的运行时动态变化。
    * 监控：开发者可以通过快照（Snapshot）来检查堆内存中分配的对象，分析哪些对象占用了内存，以及是否存在内存泄漏的情况。
    | **应用类型** | **推荐的堆内存范围** | **说明**                               |
    |--------------|----------------------|----------------------------------------|
    | 小型应用     | 1-10MB               | 简单网页应用，内存使用较低             |
    | 中型应用     | 10-100MB             | 中等复杂度应用，需注意内存管理和优化   |
    | 大型应用     | 100MB 以上           | 复杂应用，需要深入优化和监控内存使用   |

    | **浏览器** | **最大堆内存限制**   | **说明**                                 |
    |------------|----------------------|------------------------------------------|
    | Chrome     | 1.5GB 到 2GB         | 默认最大堆内存限制，移动设备限制较低    |
    | Firefox    | 1.5GB 到 2GB         | 最大堆内存限制类似于 Chrome             |
    | Safari     | 1.5GB 到 2GB         | 最大堆内存限制因版本和设备不同而异       |
    | Edge       | 1.5GB 到 2GB         | 最大堆内存限制类似于 Chrome             |

* `Documents`
    * 含义：代表当前加载在内存中的文档对象。通常，一个页面只有一个 Document 对象，但如果有 iframe 或 shadow DOM，也会增加 Document 的数量。
    * 监控：确保页面中只保留必要的 Document 对象。过多的 Document 对象可能会导致内存占用增加。
* `Nodes`
    * 含义：代表当前加载在内存中的 DOM 节点。
    * 监控：开发者应监控节点的数量，确保页面中只保留必要的节点，避免过多的节点导致内存占用过多。
* `listeners`
    * 含义：表示页面中注册的事件监听器数量。过多的事件监听器可能导致内存使用过多，尤其是那些未正确解绑的监听器。
    * 监控：开发者应监控事件监听器的数量，确保在元素移除时正确解绑事件监听器，避免内存泄漏。
* `GPU Memory`
    * 含义：这是用于渲染页面的图形处理单元（GPU）所使用的内存。包括了页面中的图像、视频、WebGL 内容等。
    * 监控：如果页面包含大量图像或视频内容，或者使用了复杂的图形渲染（如 WebGL），可能会导致 GPU 内存使用增加，进而影响性能。

### Memory Panel 快照分析

* `Distance`    
    * 含义：Distance 表示当前对象与根对象（如全局对象或 JavaScript 堆顶层对象）的最短引用路径的距离。根对象可以是浏览器环境中的全局对象（如 window）或堆内存中的其他根对象。
    * 作用：Distance 越短，表示对象离根对象越近，通常意味着这个对象更可能被引用或者更容易被访问到。较短的 Distance 值往往表明对象的重要性更高，越长则可能处于某个子对象中，较少被直接引用。
* `Shallow Size`
    * 含义：Shallow Size 表示对象本身`占用的内存大小`，不包括它引用的其他对象的内存大小。换句话说，Shallow Size 仅表示该对象的`直接内存消耗`。
    * 作用：通过 Shallow Size，你可以判断单个对象的内存占用情况。如果某个对象的 Shallow Size 很大，说明这个对象本身在内存中占用了较多空间，比如大型数组或字符串。
* `Retained Size`
    * 含义：Retained Size 表示`如果当前对象被垃圾回收器回收，可以释放的总内存大小`。这包括对象本身的内存（Shallow Size），以及所有只有通过该对象的引用才能访问到的其他对象的内存总和。
    * 作用：Retained Size 是`判断内存泄漏的重要指标之一`。一个对象的 Retained Size 较大，意味着这个对象的存在阻止了大量内存的回收。如果你发现某个对象的 Retained Size 很大，它可能是导致内存泄漏的原因。

| 内存类型| 范围  | 应用场景| 备注  |
|--|--|--|--|
| **小型对象**| `小于 1KB`| 普通的 JavaScript 对象、短字符串、小数组等   | 通常无需特别关注，除非大量创建|
| **中型对象** | `1KB 到 100KB 之间`| 较大的字符串、包含多个元素的数组或复杂的对象 | 这些对象在复杂应用中常见，但需要留意总内存  |
| **大型对象**| `100KB 到 1MB 之间`| 大型数组、包含大量数据的对象或字符串、图像数据 | 需要特别注意，如果频繁创建或长时间保留 |
| **超大型对象** | `超过 1MB`| 非常大的数据集、未优化的图像、视频帧等| 可能严重影响性能，特别在内存有限的设备上|
