# 检测数据类型

| 方法 | 适用 | 局限 |
|--|--|--|
| `typeof`（一元运算符） | 基本类型 + function | `typeof null === 'object'`（历史 bug）；数组/日期等一律 `'object'` |
| `instanceof`（二元运算符） | 判断对象是否在某构造函数的原型链上 | 对基本类型无效；跨 iframe 失效（不同全局环境的构造函数不相等） |
| `Array.isArray()` | 精准判断数组 | 只管数组 |
| `Object.prototype.toString.call()` | `万能`，所有类型返回 `[object Xxx]` | 写法长；可被 `Symbol.toStringTag` 伪造 |

```javascript
// typeof
typeof 123;          // "number"
typeof 'abc';        // "string"
typeof true;         // "boolean"
typeof undefined;    // "undefined"
typeof Symbol();     // "symbol"
typeof 10n;          // "bigint"
typeof function(){}; // "function"
typeof null;         // "object"  ⚠️ 经典陷阱
typeof [];           // "object"  ⚠️ 区分不了数组

// instanceof：沿原型链查找（原理手写见「原型与原型链」篇）
[] instanceof Array;   // true
[] instanceof Object;  // true（原型链上层也算）

// Array.isArray：跨 iframe 也可靠
Array.isArray([]);     // true

// Object.prototype.toString：一网打尽
const type = (v) => Object.prototype.toString.call(v).slice(8, -1);
type([]);          // "Array"
type(null);        // "Null"
type(undefined);   // "Undefined"
type(new Date());  // "Date"
type(/regex/);     // "RegExp"
type(new Map());   // "Map"
```

## 常见考点

* **为什么 `typeof null` 是 'object'？** JS 初版用类型标签存值，null 的机器码全零、与对象标签相同，成为无法修复的历史遗留。判断 null 直接 `v === null`。
* **为什么不用 `instanceof` 判断数组？** iframe 传来的数组其 `Array` 构造函数来自另一个全局环境，`arr instanceof Array` 为 false；`Array.isArray` 无此问题。
* **通用类型判断函数怎么写？** 就是上面的 `toString.call` 封装 —— 面试常要求现场写。

## 附：类数组转真数组

```javascript
const arrLike = { 0: 'a', 1: 'b', 2: 'c', 3: 'd', 4: 'e', length: 5 };
Array.prototype.slice.call(arrLike, 2); // ['c', 'd', 'e']（ES5 写法）
Array.from(arrLike);                    // ['a','b','c','d','e']（ES6，见 Array.from 篇）
```
