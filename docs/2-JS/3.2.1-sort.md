# sort() 方法

## 比较函数约定

`sort(compareFn(a, b))` 根据返回值决定顺序：

* `负值`：a 排在 b 前面
* `0`：保持相对顺序
* `正值`：a 排在 b 后面

## 默认行为的坑（高频考点）

不传比较函数时，sort 把元素`转成字符串按 UTF-16 编码单元（字典序）比较`：

```javascript
[10, 1, 5, 2].sort();   // [1, 10, 2, 5] ❌ 按 '1' < '10' < '2' < '5' 的字典序排

// 正确的数字排序必须传比较函数：
[10, 1, 5, 2].sort((a, b) => a - b);  // [1, 2, 5, 10] 升序
[10, 1, 5, 2].sort((a, b) => b - a);  // [10, 5, 2, 1] 降序
```

其他注意点：

* `undefined` 与空槽不参与比较，统一排到`末尾`；`null` 会被转成字符串 `'null'` 参与比较 —— 混有特殊值时先过滤。
* 中文按 Unicode 码点而非拼音排序，需要拼音序用 `arr.sort((a, b) => a.localeCompare(b, 'zh'))`。
* 对象数组按字段排：`list.sort((a, b) => a.age - b.age)`。

## 原地排序与稳定性

* sort `修改原数组`并返回它；不想动原数组用 ES2023 的 `toSorted()`（或先浅拷贝 `[...arr].sort()`）。
* 规范自 ES2019 起要求`稳定排序`（相等元素保持原相对顺序）；V8 采用 TimSort。
* 复杂度平均 `O(n log n)`。

## 常见考点

* **`sort(() => Math.random() - 0.5)` 能洗牌吗？** 不能 —— 比较结果不满足一致性，分布有偏。正确洗牌用 Fisher–Yates。
* **为什么 `(a, b) => a - b` 是升序？** a 小于 b 时返回负值 → a 排前面，即小的在前。
